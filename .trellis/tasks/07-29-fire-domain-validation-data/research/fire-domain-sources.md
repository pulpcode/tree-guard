# 消防主题公开来源与复用边界

## 问题

如何在不复制其他仓库派生数据、不引入真实业务信息的前提下，为 TreeGuard 独立
构造消防主题的小、中、大三档验证数据？

## 范围

- 日期：2026-07-29。
- 仅检查 `schema-flow` 当前文档中的来源说明、基准定位和安全提示。
- 仅检索公开政府网站上的高层消防概念。
- 未读取或导入 `schema-flow` 的树、expected、训练 JSONL、模型缓存、原始响应、
  `.env` 或 Git 历史。

## 依据

- `schema-flow/docs/project-handoff-zh.md`：消防 staging 基准由公开材料构造，
  只可用于工程验证；不是生产准确率或真实 Gold。该仓库没有许可证，且其评测
  资产已被开发过程消费。
- `schema-flow/docs/benchmark-sample-tiers.md`：异构构造树适合主要工程验证；
  “领域前缀 × 固定字段后缀”的笛卡尔积树只能作为近名/孪生字段压力测试。
- 国家消防救援局《中华人民共和国消防法》公开页面：
  https://www.119.gov.cn/site1/gk/flfg/fl/2022/18485.shtml
- 国家消防救援局《社会单位微型消防站建设标准》公开页面：
  https://www.119.gov.cn/zfxxgk/fdzdgknr/tzgg/2025/50685.shtml
- 中国政府及地方政府公开消防安全资料，用于确认疏散、消防设施、防火巡查、
  初起处置、通信和训练等均属于公开高层概念；不复制条文或数值要求。

## 结论

1. 不复制 `schema-flow` 的任何派生树、节点名集合、expected、Gold、训练数据或
   模型输出；只采用其公开总结出的评测方法教训。
2. 权威公开来源只用于确定高层覆盖类别；节点名称、层级、设施、区域、事件和
   需求全部使用自造术语独立创作，不复制真实消防字段或工程参数。
3. 小型数据承担精确合同 oracle；中型数据承担异构语义与 hard-negative 验证；
   大型数据承担 2,001 节点规模、确定性和有界输出验证。
4. 大型数据允许有系统生成的压力节点，但必须在 manifest 中明确标为
   `scale_stability`，不得代表真实 schema 或真实效果。
5. 任何人工预期只能称为合同预期或可接受候选集合，不称为生产 Gold。

## 限制

- 公开法规和指南只支持高层领域覆盖，不证明生成树符合工程设计规范。
- 本数据集不包含真实单位、真实地址、真实设备、真实检查记录或真实事故。
- 不以本数据集上的模型分数声明生产消防准确率。
