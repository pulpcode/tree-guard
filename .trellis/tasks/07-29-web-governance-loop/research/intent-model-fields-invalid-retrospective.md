# `INTENT_MODEL_FIELDS_INVALID` 复盘

## 现象

完全虚构的百炼治理请求曾通过端到端验证，后续同路径又以
`INTENT_MODEL_FIELDS_INVALID` 关闭。该错误表示模型输出的顶层字段集合不等于初始
意图合同要求的 13 个字段；本地校验器按设计拒绝输出，没有修改信息树或旁路记录。

## 根因分类

- **测试覆盖缺口**：此前只证明一次真实调用成功，以及伪 Provider 在第一次失败后
  能发起第二次请求，没有验证第二次请求是否包含足够的字段级纠错信息。
- **隐含假设**：把 `response_format=json_object` 误当作精确字段合同。它只约束
  JSON 对象，不保证无外层包装、字段齐全或没有附加字段。
- **提示合同不足**：旧初始 Prompt 只列必填字段并笼统禁止额外字段；重试只说
  “重新生成完整 JSON”，没有精确对象模板和上次失败类别。

## 修复与边界

- 初始 Prompt 升级为 `treeguard.change-intent.zh.v2`，给出精确顶层对象模板、
  缺省值编码和禁止外层包装规则；模板只约束结构，输入有直接证据时不得机械照抄
  `null`、`UNKNOWN` 或空数组。
- 至多一次纠错重试只携带固定本地错误码，不回传原始模型响应。
- 保留严格本地校验：不删除模型多余字段、不自动补字段、不把空字符串修为
  `null`。第二次仍不合格时继续失败关闭。

## 防回归证据

- 单元测试模拟模型首次返回外层包装和附加字段，验证第二次请求包含精确合同、
  `INTENT_MODEL_FIELDS_INVALID`，且不包含被拒绝响应中的标记文本。
- 提交前必须重新运行全部 Python/前端检查，并使用完全虚构数据连续执行百炼端到端
  验证；单次成功不再作为模型边界稳定性的充分证据。
- 修复过程中的真实回归曾发现精确模板诱导模型机械保留缺省值，因此继续补充字段
  语义和 hints 使用规则，而没有把一次结构成功视为完成。
- 最终 Prompt 使用 2,001 节点完全虚构树完成了意图、一次澄清、候选召回、
  语义建议和人工确认的闭环；最终状态为 `COMPLETED`，候选投影为 8 项，
  `semantic_approval`、`gold_eligible` 和 `patch_eligible` 均为 `false`。
