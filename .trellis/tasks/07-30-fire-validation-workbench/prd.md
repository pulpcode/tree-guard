# 数据集驱动的可视化验证台

## Goal

把已完成的消防主题虚构数据作为第一个数据集，通过通用数据集注册边界与 Web
治理闭环、百炼 Provider 和模型诊断连接成一个可重复运行、可对照、可回放的开发
验证台。开发者能够观察模型在具体场景中的实际输入、输出、合同校验、候选召回
和人工复核结果，而不接入生产信息树；新增其他虚构领域时不得复制治理流程。

## What I already know

- 当前已有 31、401、2,001 节点三档完全虚构消防主题数据，分别包含 8、16、24
  个场景及确定性合同 oracle。
- 当前 Web 工作台已支持意图草稿、一次澄清、Top-20 候选召回、Top-8 语义建议、
  人工确认/拒绝和可回放旁路记录。
- 当前支持 loopback 模型仿真和显式批准后的百炼真实调用，并有默认关闭的内存
  模型诊断面板。
- 当前模拟仓库只暴露一个虚构资源，消防三档数据尚未进入工作台资源目录。
- 当前 `SIMULATOR_LIVE` 从显式 clean-room 需求和 hints 生成领域中性的确定性
  合同响应，不会读取数据集中的冻结模型输出；冻结合同基线和真实模型运行必须
  分别呈现。
- 虚构场景 oracle 不是专家 Gold，不能据此声明真实消防领域准确率或生产效果。
- 产品 AI 结果和验证记录只能写 sidecar/overlay，不修改源信息树或数据库。

## Assumptions (temporary)

- MVP 先完成单场景可视化运行，再扩展小型档 8 个场景的有界批量运行。
- 批量真实模型调用需要独立的明确批准、调用上限和失败隔离。
- 初期指标只描述合同与流程表现，候选相关指标继续标记为暂定、非全树 Gold。

## Requirements (evolving)

- 页面可以选择数据档位、场景和模型模式，并清楚展示节点数、场景用途及非 Gold
  限制。
- 验证服务、HTTP 路由、DTO 和前端流程组件使用领域无关的
  `dataset_ref / variant_ref / scenario_ref`；消防名称只允许存在于消防数据集
  Provider、fixture 和展示内容。
- 新增一个可信虚构数据集时，只增加 Provider/fixture 与注册项，不修改治理
  内核、验证运行服务、通用 HTTP 合同或通用前端流程组件。
- 后端只能从仓库内可信虚构 fixture 重建树和场景，不能接受浏览器上传完整树或
  任意文件路径。
- 单场景运行复用现有应用服务与领域核心，不复制 CLI 或 Web 中的治理策略。
- 百炼真实调用继续要求显式出域批准；请求内容必须限定为完全虚构数据。
- 页面区分确定性候选召回、模型语义建议、本地合同校验和人工复核。
- 模型诊断继续默认关闭、仅本地可用、只驻留内存，不进入正式旁路工件。
- 运行结果使用独立允许列表，禁止凭据、内部路径、稳定节点 ID、完整模型 envelope
  或服务端 traceback。
- 暂定报告可包含合同通过状态、流程完成状态、澄清状态、候选预期命中情况、
  调用耗时和 Provider 明确返回的 usage；不得称为生产准确率。
- 同一冻结输入在离线确定性模式下可稳定回放；失败案例不得产生完成标记。

## Acceptance Criteria (evolving)

- [x] 页面可以选择消防虚构数据档位和具体场景。
- [x] 一个小型场景可以从需求进入意图、候选、语义建议和人工复核闭环。
- [x] loopback 与显式批准的百炼模式复用同一流程，且失败安全关闭。
- [x] 页面可查看实际模型诊断以及本地合同校验结果。
- [x] 场景结果能与合同 oracle 做有界对照，并明确显示非 Gold 限制。
- [x] 运行不修改源树，完成记录可回放且保持
  `semantic_approval=false`、`gold_eligible=false`、`patch_eligible=false`。
- [x] Python、前端测试、前端构建和 `git diff --check` 通过。
- [x] 通用验证 API、服务和前端组件不包含消防专用类型、路由或选择分支。
- [x] 使用第二个非消防测试 Provider 证明相同服务可完成目录、场景、运行和
  对照，无需修改通用实现。

## Definition of Done

- Tests added/updated（Python `unittest` 与前端聚焦测试）。
- `uv sync --frozen`、配置的 Python `unittest`、前端测试/构建和
  `git diff --check` 通过。
- 未配置的 lint、typecheck、coverage 或 CI 不报告为已通过。
- 文档说明运行模式、调用批准、oracle 边界、失败回退和未实现范围。
- 实际 diff 通过 `trellis-check` 审查并自修。
- Git 暂存和提交只在用户明确批准后执行。

## Out of Scope

- 真实消防信息树、专家 Gold、生产效果声明或生产接口写入。
- 内网 Qwen 和四类真实信息树仓库接口适配。
- embedding、向量数据库和真实全树 Recall 评测。
- 多用户鉴权、分布式任务队列、服务重启恢复和无限批量调用。
- 自动接受 AI 建议、自动生成 Patch 或修改生产数据库。

## Technical Notes

- 预计复用 `treeguard.fictional_fire_data`、现有 Workbench Governance Service、
  Provider、operation registry 和内存 diagnostics；消防数据通过
  `ValidationDatasetProvider` 注册到通用验证服务。
- 消防树应通过可信只读 Repository 接入；场景 API 只返回临时引用与安全投影，
  不把稳定节点 ID 或冻结模型输出交给浏览器。
- 首选在现有治理面板上增加场景预设和合同对照，不建立第二套治理状态机。
- 始终适用开发数据边界、确定性合同、治理接入、持久化集成和质量规范。

## Feasible Approaches

### A. 单场景预设叠加现有治理闭环（推荐）

- 将三档消防树作为可信虚构资源接入模拟仓库。
- 通过安全场景投影预填现有表单，继续调用现有治理 case API。
- 后端只返回有界合同对照，不暴露稳定节点 ID 或冻结模型输出。
- 能用最小改动验证真实模型、候选召回、诊断和人工复核。

### B. 首期直接完成批量验证

- 新增批量 job、并发/调用上限、自动场景动作和聚合报告。
- 一次得到更多结果，但会同时引入成本控制、失败恢复和自动动作语义。

### C. 增加冻结模型输出回放

- 在页面回放数据集中冻结的模型输出，结果完全确定。
- 适合演示合同，但主要重复现有测试，不能证明当前百炼模型能力。

## Decision

采用方案 A：先完成一个场景的真实端到端纵切，稳定后再把同一运行合同扩展为
小型档 8 场景批量任务。本任务不实现批量 job、自动审查动作或冻结模型输出回放。
