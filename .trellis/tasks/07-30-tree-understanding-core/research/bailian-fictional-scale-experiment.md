# 百炼完全虚构树规模实验

## 范围

- 日期：2026-07-31；
- 模型：`qwen3.6-35b-a3b`；
- 数据：仓库内独立构造的完全虚构青岚树，不含真实字段、`VALUE` 或生产标识；
- 目的：区分模型的树理解能力、结构化输出合同遵循和输入规模效应；
- 记录边界：只保存聚合计数、公开合同字段和固定错误码，不保存 Prompt、请求
  正文、原始响应或模型生成文本。

## 已完成实验

| 运行 | 投影 | Prompt / Completion tokens | 结果 |
|---|---:|---:|---|
| 小型首次 | 48 / 48 节点 | 3,904 / 862 | 合同通过；2 条 finding assessment；生成 2 个不重复场景 |
| 中型首次 | 64 / 312 节点 | 未记录 | `TREE_UNDERSTANDING_MODEL_FIELDS_INVALID` |
| 中型重试 | 64 / 312 节点 | 4,929 / 926 | 正常 `stop`；JSON object；仅缺少 `generation_status`；无额外顶层字段；合同拒绝 |

小型首次运行生成的两类 validation goal 为 `CLARIFICATION` 和
`SEMANTIC_DISTINCTION`；finding disposition 均为 `EXPECTED_PATTERN`。所有成功
或失败结果都保持非 Gold、非 Patch，失败运行没有产生部分草案。

## 当前结论

1. 中型重试正常结束并返回可解析 JSON，没有输出截断证据；当前证据不支持把
   失败归因于硬性上下文窗口耗尽。
2. 中型输入连续两次未通过顶层字段合同，第二次精确定位为遗漏
   `generation_status`，说明该规模下至少存在结构化输出遵循不稳定。
3. 中型响应在第一层合同即被拒绝，尚不能据此判断虚拟场景的语义质量。
4. 严格本地校验按设计失败关闭；不得把缺失字段静默补入正式草案。

## 下一步受控实验

对同一棵 312 节点中型树分别构建 32、48、64 节点投影，保持模型、Prompt、
finding 上限和输出合同不变，各执行一次：

- 记录 `finish_reason`、token、JSON 顶层类型、缺失/额外字段和正式合同结果；
- 若唯一缺失项是 `generation_status`，只在内存中执行一次影子补入并继续剩余
  合同校验，用于判断是否还存在深层错误；
- 影子补入结果不返回产品草案、不持久化模型文本，也不改变严格生产合同；
- 若 32、48 通过而 64 失败，形成输入复杂度阈值假设；若三档均遗漏同一字段，
  优先检查 Prompt/结构化输出约束。

## 更新后的判断

1. 三档都正常结束，Prompt 为 2,942–4,914 tokens；没有硬性窗口耗尽或输出截断
   证据。
2. 单次结果不是“节点越少越稳定”：32 节点引用失败，48 节点通过，64 节点同时
   出现字段遗漏和引用失败。
3. 64 节点在首次、重试和本次对照中均未通过正式合同，其中两次已精确定位为
   遗漏 `generation_status`；该规模的合同遵循风险已重复出现。
4. 48 节点的一次成功不足以证明稳定阈值；下一步需要重复同字节请求，估计各档
   合同通过率，并把引用失败按“空、格式、越界、顺序、重复”做非内容分类。
5. 当前不修改严格 parser，不把影子补入升级为产品 fallback。

## 后续重复性实验

建议对同一份 32、48、64 节点请求各追加两次调用，形成每档三次观测：

- 使用完全相同的请求字节，不修改 Prompt 或投影；
- 分别记录正式通过率、字段遗漏率、引用失败分类和 token；
- 仍只在唯一缺失 `generation_status` 时做诊断性影子补入；
- 若 48 节点保持显著更高通过率，再形成暂定运行上限假设；否则先增强结构化
  输出约束，而不是调整树扫描或语义数据。

## 重复性结论

1. 32 与 48 节点正式通过率均为 1/3，不能把 48 节点视为稳定阈值；64 节点
   0/3，且字段遗漏具有重复性。
2. 多数 node ref 失败来自合法引用没有升序排列，而不是模型编造或越界引用。
3. 本地 parser 要求场景引用升序、唯一；当前 Prompt 明确要求从允许列表逐字
   复制，但没有同等明确地要求升序和唯一，存在合同表达缺口。
4. 下一步先进行最小 Prompt A/B：保持 projection、parser、Schema 和数据不变，
   只明确引用升序唯一，并再次强调 `generation_status` 必须出现。
5. A/B 首轮只测试 48 和 64 节点各一次；通过本地虚构 transport 后才冻结并审批
   新的百炼请求字节。

1. Prompt v4 在首轮同时消除了已观测的引用排序错误和 64 节点

2. v4 每档只有一次观测，不能直接声明稳定通过率或 64 节点已经可靠。
3. 下一步若继续评估稳定性，应使用完全相同的 v4 请求各追加两次，再与 v3 的

4. 在重复性证据形成前，不调整默认 64 节点上限，也不放宽严格 parser。

## 下一决策点

`supporting_node_refs` 和 `source_finding_refs` 的成员集合承载语义，数组顺序只为
规范序列化服务。后续有两条路径：

1. 保持当前严格顺序合同，依赖 Provider 第二次完整重试，继续承担格式性失败；
2. 只对已验证为格式合法、属于允许列表且无重复的引用做本地升序规范化，仍拒绝
   空引用、未知引用、格式错误和重复引用。

路径 2 不增加、删除或替换模型引用，只规范无语义顺序，但它改变当前“不修正
N/D/S 引用”的严格边界，实施前必须更新 PRD、规范、测试和回放合同。

## 合同决策

项目决定采用路径 2：

- 场景的 `supporting_node_refs` 与 `source_finding_refs` 按无优先级集合解释；
- parser 先验证数组边界、非空支持引用、引用格式、允许列表和唯一性，再统一
  升序构造不可变草案；
- 输入顺序不进入草案语义或 digest；
- 未知、重复、格式错误和空的支持引用仍使用原固定错误码拒绝；
- finding assessment 顺序和连续 `S` 场景引用仍保留原有语义合同，不做排序
  归一化。

模型输出 Schema 已使用 `uniqueItems` 且未声明数组顺序，无需升级 Schema 版本。
Prompt 升级为 v5，明确引用数组顺序不表示优先级并由本地规范化。

`NEED_EVIDENCE` assessment 和 2 个虚拟场景，均保持待人工审核、非 Gold、

| 投影 | 清晰性 | 可执行性 | 证据关联 | 场景差异性 | 不过度声称 | 合计 |

| 48 / 312 | 2 | 1 | 2 | 1 | 2 | 8 / 10 |

聚合缺陷类别：

- 48 节点场景偏向让用户执行属性定义审查或建模分析，和最终用户直接提出的信息

本节不保存模型生成正文、请求、响应 envelope 或内部稳定 ID。

## 完整 48 节点控制树重复性结果

对完整覆盖 48/48 节点、包含 2 条确定性 finding 的同一 v5 请求连续执行三次；
三次均通过完整本地合同，每次均返回 2 条 `NEED_EVIDENCE` assessment 和 2 个
虚拟场景，且保持待人工审核、非 Gold、非 Patch。

人工 rubric 的三次聚合表现为：清晰性稳定为 2/2，可执行性与场景差异性均为
1/2，证据关联和不过度声称在 1--2/2 之间。主要观察：

- 六个场景全部由两条同名复用 finding 驱动，没有覆盖其余正常业务分支；这证明
  当前链路稳定生成质量审查问题，但不能证明全树业务理解或代表性需求生成。
- 三次引用成员、父子关系和 finding 绑定均合法，没有投影外引用；但两次摘要将
  “总计 48 节点”表述为“根节点及 48 个子节点”，存在轻微计数语义偏差。
- 两次草稿在 assessment 明确需要证据时仍返回空 uncertainty/evidence gap，说明
  顶层合同通过不保证跨字段语义一致。
- 生成问题多为属性定义、计数口径和跨分支同名比较，偏数据治理人员，不足以达到
  “多数问题可由普通用户直接提出”的实验门槛。

因此本轮对“finding 驱动的质量检测投影”判定为可行，对“通用信息树理解 Agent”
判定为证据不足。后续应把正常业务需求生成与 finding 质量检测拆成独立输入目标，
再验证分支覆盖和用户问题自然性。本节仍只保存聚合观察，不保存模型生成正文。

数量或期限组合进同一场景。除此之外，模型自主选择的有效场景集中在服务空间和
公共活动，没有形成代表性四分支覆盖。第一、二轮还分别出现一个问题包含多个
信息诉求、但支持引用只覆盖其中一部分的情况；第三轮的问题—引用完整性明显改善，
说明该能力存在单次波动。

本轮还暴露出实验合同的层次差异：现有 parser 只校验引用合法、唯一和存在于投影，
不会校验 Prompt 新增的“必须显式包含一级分支”和“同一场景不得跨一级分支”规则，
因此合同 3/3 通过不等于业务规则通过。显式一级分支引用本身是便于审计的冗余证据，
本地可以从后代引用确定性推导归属；但跨分支引用和问题诉求缺少证据不能通过这种
推导修复。

当前结论：

1. 模型能够从完整节点投影自主概括树的四个主要业务区域，并生成自然的问题；
2. 单次自由生成不能可靠承担代表性抽样，且会稳定复现一个看似自然但结构归属错误
   的跨分支组合；
3. 信息树理解 Agent 不应把“让 LLM 自由读全树并出题”作为唯一实现逻辑；应由
   本地确定性规划器先分配覆盖目标和候选子树，再让 LLM 在单分支证据范围内生成
   问题；
4. 输出后至少要确定性校验支持引用的共同一级祖先，并进一步审核问题中的每个信息
   诉求是否都有支持证据；
5. finding 驱动的质量检测、受控分支场景生成和自由业务探索应作为三个不同模式，
   分别设定输入、验收标准和人工复核边界。

本节仍不保存 Prompt、响应 envelope 或模型生成正文。
