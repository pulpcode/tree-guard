# M3 百炼 312 节点虚构树场景准备实验

## 范围与数据边界

- 日期：2026-08-02；
- 模型：`qwen3.6-35b-a3b`；
- 数据：仓库内独立构造的 312 节点青岚完全虚构树和 M3 新节点 overlay，不含真实
  字段、`VALUE`、生产标识或受保护材料；
- 目的：验证 M3 确定性计划、逐单元有界投影、真实模型合同遵循、部分失败归并，
  并由 Codex 在输出完成后审核自然语言、风险族和结构证据的一致性；
- 外发边界：用户单独批准了 26 个精确可能请求体，每个计划单元只允许首发一次及
  合同失败后重试一次；批准载荷及其哈希不写入任务工件；
- 记录边界：不保存 Prompt、请求正文、原始响应、模型生成文本、凭据或账号端点；
  本文只保存聚合指标、固定错误码和缺陷类别。

## Transport 与本地合同结果

| 指标 | 结果 |
|---|---:|
| 计划单元 | 13 |
| 实际 HTTP 调用 | 14 / 26 上限 |
| 首发 / 合同失败重试 | 13 / 1 |
| 正常返回 / `finish_reason=stop` | 14 / 14 |
| Prompt / Completion tokens | 51,820 / 5,019 |
| 最终候选 / 失败 / 未执行 | 12 / 1 / 0 |
| 批次状态 | `PARTIAL` |
| 投影节点覆盖 | 238 / 312（76.3%） |
| 未投影节点 | 74 |

- 12 / 13 个单元首发即通过完整本地合同；一个分支覆盖单元首发失败后按批准清单
  重试一次，仍以 `SCENARIO_PREPARATION_MODEL_ASPECT_EVIDENCE_INVALID` 失败；该错误表示
  `requested_aspects` 没有精确覆盖模型声明的全部支持引用；
- 该单元两次响应都正常结束，Prompt 仅约 1.1k tokens，明显小于其余多数单元的
  约 4.1k tokens。本次没有截断、窗口耗尽或 transport 故障证据，不能把失败归因
  于 312 节点树或上下文窗口；
- 八个风险族的机器状态均为 `CANDIDATE_READY`，原因是每个族至少存在一个通过
  形状与引用合同的候选。该状态只说明机械归并结果，不表示候选自然语言真正表达
  了相应风险。

四类覆盖分别披露，不能合并为“理解率”：

- 风险族：8 / 8 为机械 `CANDIDATE_READY`，语义审核结果见下节；
- 分支基础单元：计划 5 个，4 个形成候选，1 个合同失败；
- 目标阶段：`INTENT` 形成 3 / 3 个候选，`RETRIEVAL` 形成 5 / 6 个，
  `RECOMMENDATION` 形成 4 / 4 个；本实验只准备候选，三个阶段的 MVP 执行状态
  均为 `NOT_RUN`；
- 投影节点：跨单元唯一并集为 238 / 312，遗漏 74，`coverage_complete=false`。

## Codex 输出后语义审核

隐藏参照只在完整模型批次形成后读取。审核采用以下保守口径：是否形成自然且实质
的结构建模/变更诉求，是否符合计划风险族与目标阶段，诉求中的信息是否均有树证据，
是否可映射到 MVP 请求，以及是否避免把基数、局部投影或缺失实例值过度解释为业务
事实。审核只用于候选分级，不构成专家审批或 Gold。

| 分级 | 数量 | 含义 |
|---|---:|---|
| 可原样进入后续人工筛选 | 3 / 12 | 诉求、结构证据和计划目标基本一致 |
| 语义方向可保留但必须修订 | 4 / 12 | 存在临时引用进入用户文本、范围不够明确或证据外推等问题 |
| 拒绝 | 5 / 12 | 自然语言仍为模板占位文案，不能形成可执行测试请求 |
| 无候选 | 1 / 13 | 一个分支覆盖单元两次均未通过本地合同 |

沿用父任务每项 0--2 分的五维 rubric，12 个合同候选的 Codex 聚合评分如下。该
评分只用于比较生成质量，不是专家语义裁决：

| 维度 | 聚合得分 |
|---|---:|
| 清晰性 | 14 / 24 |
| 可执行性 | 10 / 24 |
| 证据关联 | 15 / 24 |
| 风险族与目标区分 | 16 / 24 |
| 不过度声称 | 12 / 24 |
| 合计 | 67 / 120 |

按计划角色进一步观察：

- 8 个风险挑战单元中，2 个可原样筛选、2 个需修订、4 个应拒绝；
- 7 个既有隐藏参照映射中，2 个达到明确的风险结构等价、1 个部分等价、4 个未能
  在自然语言中体现被分配的风险；新增节点 overlay 对应候选达到结构等价；
- 5 个分支覆盖单元中，1 个可原样筛选、2 个需修订、1 个应拒绝、1 个合同失败；
- 5 / 12 个合同通过候选直接保留了对象模板的通用占位文案；本地 parser 只验证
  文本非空、固定字段、引用集合和来源绑定，因此这些候选仍被机械接受；
- 其余缺陷集中在：把投影临时引用写入面向用户的需求、用单值基数推断“必填”、
  叙述了没有支持引用的同级字段，以及无界组合/证据不足场景没有明确保留不确定性
  或证据缺口。

## 判断

本轮证明真实百炼路径已经可以安全执行确定性 13 单元计划：批准门、逐单元投影、
严格引用合同、最多一次合同重试、失败后继续和 `PARTIAL` 归并均按设计工作。它也
证明 312 节点源树不需要整体塞进一个上下文，14 次调用没有出现规模性 transport
或窗口故障。

本轮不能证明模型已经可靠理解信息树，也不能把八个 `CANDIDATE_READY` 当作八个
风险族语义通过。当前主要瓶颈已经从 JSON/引用形状转移到“计划风险如何被真实写进
自然语言需求”以及“每项诉求是否由引用证据支持”。这些候选仍为
`UNVERIFIED_MODEL_GENERATION`、`PENDING_HUMAN_REVIEW`、非 Gold、非 Patch，
不应注册为验证数据集。

## 建议的下一步

1. 移除可被原样复制的自然语言模板占位值，改用最终输出禁止出现的哨兵，并在本地
   明确拒绝未改写哨兵；
2. 为八个风险族增加确定性的任务语义和最小输出政策，例如证据不足必须披露
   `evidence_gaps`，无界组合必须表达缩小范围或拒绝，类型/基数冲突必须在诉求中
   出现冲突双方；
3. 禁止 `requirement_text` 包含投影临时引用，并明确“`SINGLE` 不等于必填”；继续
   保留 Codex/人工对自然语言—证据完整性的审核，不用 parser 猜测领域语义；
4. 完成本地 fake-transport 回归后，重新冻结同一 312 节点输入的新请求字节，再
   独立审批一次百炼 A/B。现阶段不需要新增测试树，先用相同数据隔离 Prompt 与
   合同改进效果。
