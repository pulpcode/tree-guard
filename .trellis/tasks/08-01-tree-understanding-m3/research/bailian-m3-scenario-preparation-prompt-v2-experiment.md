# M3 Prompt v2 百炼 312 节点虚构树场景准备复验

## 范围与数据边界

- 日期：2026-08-02；
- 模型：`qwen3.6-35b-a3b`；
- 数据：仓库内独立构造的 312 节点青岚完全虚构树和 M3 新节点 overlay，不含真实
  字段、`VALUE`、生产标识或受保护材料；
- 目的：在相同树和 13 单元确定性计划上，复验 Prompt v2 的真实模型合同遵循、
  条件重试、归并结果和已知文本缺陷 canary；
- 外发边界：只使用单独批准的 26 个可能请求体；每个单元首发一次，只有本地合同
  失败时才允许对应重试一次；
- 记录边界：审批载荷及哈希、端点、Prompt、请求正文、原始响应、模型生成文本和
  凭据均不写入任务工件；本文只保存聚合指标、固定错误码和限制。

## 与 Prompt v1 实验的可比结果

| 指标 | Prompt v1 | Prompt v2 |
|---|---:|---:|
| 实际调用 | 14 | 16 |
| 首发通过 | 12 / 13 | 10 / 13 |
| 最终候选 | 12 / 13 | 13 / 13 |
| 最终合同失败 | 1 | 0 |
| 批次状态 | `PARTIAL` | `SUCCESS` |
| Prompt + Completion tokens | 56,839 | 72,587 |
| 旧版占位文案 | 人工审核发现 5 / 12 | canary 为 0 / 13 |

Prompt v2 的合同更严格，首发通过率反而下降，且本轮总 token 比 v1 增加约 27.7%；
但完整重试把三个合同失败全部恢复，最终候选完整度从 12 / 13 提高到 13 / 13。
因此当前改进主要体现在“已知坏文本失败关闭”和“重试后合同完整”，不能解释成模型
本身已经更稳定或理解率达到 100%。

## 独立语义审核取样

为完成可比语义审核，另行批准同一精确请求集再运行一次，并只把本地合同解析后的
候选草稿短期写入权限为 `0600` 的私有临时工件；没有保存原始响应 envelope。第二次
运行的 transport 聚合如下：

| 指标 | 第二次运行 |
|---|---:|
| 实际 HTTP 尝试 | 13 / 26 上限 |
| 首发 / 重试 | 13 / 0 |
| 正常结束 / `finish_reason=stop` | 13 / 13 |
| Prompt / Completion tokens | 52,739 / 4,401 |
| 最终候选 / 失败 | 13 / 0 |
| 批次状态 | `SUCCESS` |

两次 Prompt v2 运行使用相同请求字节，最终均为 13 / 13 候选；但第一次有三个首发
合同失败，第二次全部首发通过。即使请求声明温度为零，也不能把远端服务假定为严格
逐字或逐次可重复；当前只能认为“最终合同成功 2 / 2”，不能认为首发行为稳定。

候选生成完成后才打开隐藏参照。审核继续沿用 v1 每项 0--2 分的五维 rubric；隐藏
参照只用于检查风险方向，不作为 Gold。聚合结果如下：

| 维度 | Prompt v1 | Prompt v2 |
|---|---:|---:|
| 清晰性 | 14 / 24 | 23 / 26 |
| 可执行性 | 10 / 24 | 18 / 26 |
| 证据关联 | 15 / 24 | 20 / 26 |
| 风险族与目标区分 | 16 / 24 | 21 / 26 |
| 不过度声称 | 12 / 24 | 14 / 26 |
| 合计 | 67 / 120 | 96 / 130 |

| 分级 | Prompt v1 | Prompt v2 |
|---|---:|---:|
| 可原样进入后续人工筛选 | 3 / 12 | 3 / 13 |
| 语义方向可保留但必须修订 | 4 / 12 | 8 / 13 |
| 拒绝 | 5 / 12 | 2 / 13 |
| 无候选 | 1 / 13 | 0 / 13 |

Prompt v2 的平均 rubric 得分从约 55.8% 提高到约 73.8%，拒绝和无候选明显减少；
但可原样筛选仍只有 3 条，没有增加。8 个风险挑战单元中为 2 条可筛选、5 条需修订、
1 条拒绝；5 个分支覆盖单元中为 1 条可筛选、3 条需修订、1 条拒绝。这说明 v2 主要
把“不可用”提升成“可修订”，尚未把候选生成提升到可免人工审核的程度。

主要剩余缺陷为：

1. 临时投影引用仍可进入 `rationale`；当前确定性门禁只覆盖
   `requirement_text`，与 Prompt 所称“仅出现在结构化引用字段”不完全一致；
2. 部分候选仍包含“验证系统”“主要锚点”“检索阶段”等实验或实现元叙述，不像
   自然用户需求；
3. 已有节点复用有时被写成读取或填写“属性值/具体内容”，但信息树只提供结构定义，
   没有实例值；
4. 个别候选从节点名称外推出未投影的业务事实、编码格式、有效性规则、完整交互逻辑
   或“当前缺失”等结论；“不过度声称”仍是相对最弱的维度；
5. 无界组合候选把“如何缩小范围”直接写进需求，提前替 MVP 完成了应被识别的风险，
   不再是自然的过宽用户诉求；
6. 证据不足候选虽有非空 `evidence_gaps`，但仍使用通用缺口文案，没有具体列出完成
   业务判断所缺的结构或实例证据。

## 限制与下一步

1. A/B 语义审核已完成，但仍是单次 13 候选样本，不代表生产领域、不同树或模型版本；
2. 下一版确定性合同应先把临时投影引用禁令扩展到全部自然语言字段；这属于可证明的
   合同一致性修复，不需要模型或本地代码猜测领域语义；
3. Prompt 应进一步区分结构节点与实例值，并要求风险族任务生成自然用户诉求：无界
   组合的缩小范围建议只放在 uncertainty，证据不足的缺口必须具体改写；
4. 三次相同的 aspect-evidence 首发失败说明提示仍可减少引用集合误差；后续优化不能
   由本地静默修改模型的诉求—证据声明，只能继续强化输出说明或保持失败关闭；
5. 机械合同、Codex 语义审核和最终专家审核必须继续分层；3 条“可原样筛选”也仍是
   待人工候选，不能自动成为 Gold、Oracle、Patch 或生产写入依据；
6. 私有候选审核工件在聚合结论落库后删除，不把模型原文、审批哈希或端点写入任务。

## Prompt v3 本地落地状态

2026-08-02 已根据上述语义审核完成 Prompt v3 的本地最小修订：第四个 evidence-gap
哨兵进入统一文本政策，独立 `N/D/S` 临时引用禁令扩展到五类自然语言字段，Prompt
明确结构定义与实例值边界、自然用户视角、无界需求、具体证据缺口和基数一致性。
模型输入/输出及候选 Schema、计划算法、投影版本和单元尝试上限均未改变。
当前验证器对直接构造、模型解析和存储回放统一失败关闭，不以候选自带的 Prompt
版本放宽旧文本；因此包含新增受禁临时引用的历史 v2 草稿不会通过当前回放。两次
实验的候选原文均未落库，且这些候选从未成为 Gold，此处没有需要迁移的持久化数据。

本地聚焦测试 34 / 34、完整后端测试 374 / 374、前端测试 13 / 13 和构建均通过；
Trellis task validate 与 `git diff --check` 通过。该实现过程没有读取工作区 `.env`、
没有生成或保存新的模型请求/响应，也没有模型或百炼网络调用。以上只证明 v3 合同
与 Prompt 文字已经落地，不能证明真实模型语义质量提升；下一次百炼 A/B 仍需重新
冻结最终请求字节、单独批准，并在生成后按相同五维 rubric 审核。
