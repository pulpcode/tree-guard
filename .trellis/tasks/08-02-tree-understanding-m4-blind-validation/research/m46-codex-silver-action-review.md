# M4.6 Codex 辅助 Silver 行动复核

## 范围与约束

- 复核对象：M4.6 中 7 条 `ADD_NODE_FROM_CONTRACT / UNSAFE_MISMATCH`；
- 复核等级：`CODEX_ASSISTED / SILVER`，固定非 Gold、非门禁、非 Patch；
- 复核时点：已看到模型结果后的事后诊断，不具备预注册或未见数据属性；
- 原模型结果、原 Oracle 和 M4.6 主评分保持不变；
- 私有 sidecar 只保存来源绑定、固定 decision/reason code 和运行内引用，不保存模型
  请求、理由或响应正文；仓库只记录以下聚合。

## 结果

| Codex Silver 判定 | 数量 |
|---|---:|
| 可接受替代 | 0 |
| 证据正确、动作错误 | 1 |
| 证据与动作均有实质错误 | 6 |
| 建议扩宽 Oracle | 0 |

按风险族进一步定位：

- Top-K 边界 3 条：1 条找到了正确证据，但把“使用既有节点”误判为“基于合同新增”；
  另 2 条在正确目标已经可见时仍选择了错误分支的同名合同；
- 基数冲突 2 条：模型把结构字段一致当成业务语义一致，混淆了两个不同的业务对象；
- 显式空目标 2 条：模型忽略请求中的空目标约束，并为值类型和业务语义均不匹配的
  候选构造了“可复用合同”解释。

因此 7 条仍全部保留为 M4.6 `UNSAFE_MISMATCH`，不降级为
`SAFE_ALTERNATIVE`，也不形成当前 Oracle 修订。

## 解释与限制

这次复核把“模型能力问题”从笼统的不正确收窄为三类可验证问题：动作语义混淆、
错误分支选择，以及用结构相似替代业务语义。它同时排除了“这 7 条主要是 Oracle 过窄”
这一解释。

但该结论仍来自已揭盲 Silver，不能证明下一版 Prompt 或门禁会泛化。后续若据此设计
通用合同或 Prompt A/B，必须先冻结规则，再用不同场景和新密封数据验证；不能在当前
7 条上修改后把同一批结果重新计为能力提升。
