# M4.9 未见性与防过拟合合同

## 要证明的不是“模型从未见过消防”

本轮只能证明：在当前仓库和本项目可审计实验范围内，冻结后的新树、场景正文、目标
和 Oracle 在首次正式请求前没有进入既往模型调用，也没有用于修改当前功能基线。
无法证明基础模型训练阶段从未见过相似公开概念，也不能外推到仓库外未知实验。

## 按构造实现未见性

1. 数据 worktree 固定从功能提交
   `d52e92341b1d081c45c9e4594b98323327379da5` 创建。
2. 数据作者只读取公共 Schema、功能合同、数据 Skill 和历史聚合指标/固定错误码；
   不读取或复用历史 Prompt、请求、响应、场景、目标、Oracle 和人工答案正文。
3. 新树从空蓝图独立生成；不把任何既有 fixture 作为模板、seed、词库或结构骨架。
4. 数据侧先冻结树、正式 24 条、余量、Oracle、审核记录和各自 digest，再向功能侧
   只交付 identity、规模、覆盖计数、合同绑定与 digest。
5. 功能侧先冻结模型/endpoint/参数/重试/比较器和精确运行 manifest，之后才能读取
   执行正文并发起请求。
6. 所有运行完成并冻结原始私有结果后才揭盲评分；Oracle 不进入模型投影。

## 可审计证据

第二阶段 preflight 必须产生不含正文的聚合证据：

- 新树 canonical digest 与 fixture SHA；
- 正式场景批次、余量批次、Oracle sidecar、审核包和运行 manifest 的独立 SHA；
- 功能提交、Intent/Semantic Prompt 版本、召回算法、比较器和门槛版本；
- 首次请求前，对仓库既有实验聚合记录中的 dataset identity/digest 做零命中检查；
- 模型输入允许列表 canary 检查，证明不含 Oracle、稳定 node ID、审核字段和目标答案；
- 时间顺序：`feature freeze < data freeze < run config freeze < first request < unseal`。

摘要匹配只证明完整性和仓库内零命中，不是身份认证，也不用于脱敏低熵真实数据。

## 信息隔离角色

| 角色 | 可以看 | 不可以看 |
|---|---|---|
| 功能实现侧 | 本规划、功能合同、聚合历史结论 | 新树/场景/Oracle 正文，直到实现与运行配置冻结 |
| 数据作者 | 公共合同、新树与候选 | 历史模型原始输出、针对单条失败的修复建议 |
| Oracle 审核者 | 冻结树、场景、候选 Oracle | 本轮模型响应与逐轮成绩 |
| 执行器 | 冻结模型投影和请求计划 | 隐藏 Oracle 与审核意见 |
| 评分器 | 已冻结运行结果与 Oracle | 修改 Prompt、候选、Oracle 或阈值的权限 |

同一个 Codex 会话可以提供 Silver 辅助，但不能因此声称独立双审。若角色无法由不同
人员承担，至少必须以不可变 digest 和时间顺序实现职责隔离，并降低结论等级。

## 防止针对历史错误过拟合

- 历史结果只允许以类别级事实进入规划，例如“存在字段合同失败、连接波动、错误
  复用或跨分支混淆”，不得把具体请求、具体词对、具体目标或模型理由写入蓝图。
- 覆盖格在树和场景正文生成前冻结。不得因为已知模型容易混淆某两个词，就创建对应
  同义替换题。
- 正式集由结构配额、顶层分支覆盖和固定 seed 选择，不由模型预跑成绩选择。
- 数据冻结前不调用被测模型做筛题；L2 Critic 只能审可答性和数据质量，不能预测或
  优化被测模型分数。
- 评分政策允许多个人工认可的联合结果，但必须在模型运行前冻结；运行后发现的合理
  新答案只能形成未来政策候选，不回填当前分数。
- Prompt、代码、模型、参数、重试、K、Oracle 或阈值只要在揭盲后变化，当前数据就
  永久标记为 `CALIBRATION_ONLY`；再次门禁必须另建新数据。

## 污染与降级矩阵

| 事件 | 处理 |
|---|---|
| 功能侧在冻结前意外看到新正文 | 停止；重新生成新的树和场景 identity |
| Oracle 进入模型输入或 retry Prompt | 立即停线，当前批次作废 |
| 被测模型用于候选筛选或改写 | 当前批次仅可作为校准数据 |
| 揭盲后修改功能或评分再重跑 | 允许回归观察，但不得再称泛化验证 |
| 只重试同一逐字节请求以诊断传输/随机波动 | 按预注册重复合同记账，不算数据污染 |
| 历史聚合记录出现新 digest 零命中失败 | 停止并调查，不能声明未见 |
| 仓库外是否见过无法证明 | 在结论中明确限制，不伪造证明 |

## 成功解释

只有新密封数据达到预注册门槛，才能说明“当前技术路径在另一棵同领域树上表现出
可重复的泛化迹象”。它仍不能证明模型理解所有信息树，也不能替代受保护环境中的真实
用户需求、真实树分布、时延、权限和人工可用性验证。
