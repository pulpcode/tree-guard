# 人工审核、交接与停线

## 两次不同目的的人工审核

### 调用前：24 条正式场景与 Oracle

获授权人员通过私有 HTML 逐项检查最终树证据、request、Intent route、可接受召回
目标、首选联合结果和允许安全退让的条件。

- 必须审核 24/24；不使用抽样代替；
- `reviewed_scenario_count=24` 且 authority 为 `HUMAN_AUTHORIZED`；
- 审核绑定最终字节 digest；任何改动使旧审核失效；
- Codex 可以预先标记固定 finding code，但不能代替最终人工状态；
- HTML 与完整审核内容保持私有，不写入公开报告。

### 调用后：不同的安全退让输出

对所有不同的 `SAFE_ALTERNATIVE` 输出检查问题质量与误导风险。逐字节相同输出可以
去重，不同文本不能仅因动作枚举相同而合并。

至少检查：

- 问题是否原子且用户可回答；
- 是否错误暗示修改、忽略或绕过树合同；
- 是否把结构定义误当实例值；
- 是否诱导不安全正向操作；
- 是否泄漏内部标识、目标答案或系统 Prompt。

## 审核预算候选

| 项 | 上限 |
|---|---:|
| 调用前正式场景 | 24 条，全量 |
| 调用前余量 | 仅实际启用项，最多 6 条 |
| 单条修订 | 最多 2 轮 |
| 整批修复 | 最多 3 轮 |
| 调用后安全退让 | 全部不同输出，最多 54 个正式 Semantic observation |
| 调用前人工预算 | 240 分钟 |
| 调用后人工预算 | 180 分钟 |

## 停线条件

任一情况立即停止，不通过放宽 Oracle 或删除失败样本继续：

- 数据边界、来源分类或历史正文派生不成立；
- Oracle、稳定目标、审核结论或 canary 进入模型输入；
- 树、场景、Oracle、审核、配置或运行工件来源绑定失败；
- 24 条正式场景未全部人工审核；
- 首次模型调用后替换候选、修改正文、Prompt、模型、参数、K、阈值或比较器；
- Intent MISMATCH/RUN_FAILED 后仍执行 Retrieval，或 Retrieval 非 MATCH 后仍执行
  Semantic；
- 出现未解释的笛卡尔积密度、重复子树或编号兄弟扩张；
- 单条超过两轮修订、整批超过三轮修复或人工预算超限。

## 交接顺序

```text
冻结 Charter/覆盖/效用门
→ 生成候选 staging
→ L1 确定性 preflight
→ Codex 非权威预检
→ 人工 HTML 审核 24/24
→ 冻结数据与运行配置
→ 构建精确请求计划
→ 三轮执行并按阶段短路
→ 冻结私有结果
→ 揭盲评分
→ 人工审核不同安全退让
→ 构建 M5 聚合准入报告
```

效用门合同已实现，且同领域独立树方案已经确认；当前可推进候选生成、确定性
preflight、Codex 非权威预检和私有审核 HTML，人工审核完成前仍不得进入模型执行。
