  链路不可达，因此本轮最终记为 `DATA_OR_RUN_INVALID`，仅保留诊断价值；
- b02 已揭盲，不得通过修改 Prompt、Oracle、Policy 或阈值后再次用于资格晋升。

80轮中有70轮初次理解触发澄清并跳过 Semantic，只有10轮执行 Semantic；Semantic 调用均
未退化。理解降级固定错误集中在 hint 冲突和澄清后 TARGET span 无法回绑。该分布说明：

1. 当前理解 Prompt 对“何时必须澄清”的边界过宽，模型把候选、上下文或信心不足也转换
   成澄清；
2. 一旦误触发澄清，两调用预算会固定跳过 Semantic，Policy 退化为 `NEED_EVIDENCE`，形成
   路由错误向下游放大的级联；
3. b02 澄清 Oracle 又要求不可达的 `AMBIGUOUS`，使资格实验本身存在合同缺陷；
4. 召回在本轮不是主要退化来源：R0 和 C1 均为41/42，且 C1 无帮助也无伤害。

## 后续约束

- runner preflight 必须在 Provider 创建前拒绝不可达澄清 Oracle；
- 理解 Prompt 只允许在需求原文本身存在至少两个互斥、阻断 TARGET 判定的解释时澄清；
- 非空结构 hint 视为可信约束，模型必须原样采用；
- 修复只在开发集验证，不得重跑 b02 形成资格结论；
- 下一次资格运行必须使用新的 clean-room 树、场景、Oracle 和独立 execution manifest。
