# 生产 Shadow 启用前审计

## 范围

- 审计基线：`95e8f99e9227e992a84e7ddd157588087d25436f`；
- 仅检查本仓库的导航 Copilot 合同、Workbench 状态机、私有 sidecar 和聚合输出；
- 未访问受保护环境、真实信息树、真实请求、模型流量或生产配置。

## 结论

当前实现已具备受保护环境内的**单 case 安全演练能力**，但首轮 30 case 生产
Shadow 暂为 `NO_GO`。阻塞点不是召回模型效果，而是 D10 的运行分母尚不能从现有
工件中得到可信、可回放的计算。

## 已满足的启用基础

- feature path 缺省关闭，关闭时不创建 Copilot service 或 sidecar；
- 单 case 最多两次逻辑模型调用，理解和 Semantic 失败均有安全降级；
- 候选选择只产生导航引用和私有运营反馈，不修改树、数据库或 Patch；
- outcome、候选和树快照存在确定性绑定，私有文件不可覆盖发布；
- API 聚合不包含请求正文、稳定节点 ID、模型原始流量、路径或 hash。

## 阻塞项

### R1：目标存在性的分母不完整

现有 outcome 只有 `SELECT_CANDIDATE / SELECT_OUTSIDE_CANDIDATE / REJECT_ALL / EXIT`。
`REJECT_ALL` 同时可能表示：

1. 树中确有目标，但 Top-8 漏召回且用户没有完成候选外定位；
2. 树中不存在目标；
3. 用户无法判断目标是否存在。

因此现有聚合不能可靠计算“树中确有目标”的分母。若直接以已完成导航数作为分母，
导航完成率会退化为恒等式，无法验证 D10 的 90% 门槛。

### R2：参与者数量没有可信绑定

当前 case、sidecar 和聚合均不记录运行内匿名参与者引用，也没有认证层。仅凭人工说明
无法从冻结工件证明覆盖了至少 3 名用户。

### R3：聚合只存在于单进程内存

Workbench 重启后聚合重新计数。首轮 30 case 若跨进程或跨参与者实例运行，当前 API
不能把多个私有 sidecar 确定性合并为一个冻结分母。

### R4：运行资格没有冻结绑定

现有 capability 能证明代码路径不提供生产写入，但没有把代码提交、合同版本、Provider
模式、参与者配额、计数起点、停止条件和阈值绑定为一个不可变的 Shadow run manifest。
若在观察结果后补充这些信息，会削弱预注册价值。

## 推荐的最小修复路径

首轮采用**每名参与者一个受保护 Workbench 实例 + 私有离线汇总**，不在本轮引入共享服务
认证、多 worker 或数据库：

1. 新增冻结的 run manifest，绑定代码提交、合同版本、固定 D10 阈值、Provider 模式、
   参与者匿名引用、计划 case 数和安全停线规则；
2. 把人工终态拆分为“已选中候选”“候选外纠正”“确认目标存在但未找到”“确认树中无
   目标”“无法判断”“退出”，使目标存在分母可计算；
3. 每个私有 sidecar 绑定 run 与匿名参与者；API 仍不返回参与者引用；
4. 新增只读取获批准私有目录的确定性离线聚合器，严格回放 sidecar，输出固定聚合字段，
   不输出请求正文、内部节点 ID、路径、hash 或参与者引用；
5. preflight 在首个 case 前冻结 30 case、至少 3 名参与者和 D10 阈值；任一安全指标失败
   立即停线，效果指标只在冻结分母完成后判断。

## 暂不采用

- 不直接用现有进程内 aggregate 作为 D10 晋升证据；
- 不用人工补表替代目标存在性和参与者绑定；
- 不为了首轮 30 case 引入共享登录、生产数据库或跨进程在线状态服务；
- 不在修复分母前开始采集正式样本。

## 后续修复状态

本审计提出的仓库侧修复现已实现：冻结 run manifest、匿名参与者绑定、独立目标状态资格
记录和跨实例私有离线聚合均已加入，并通过完整回归。该实现消除了本审计所述的分母恒等、
参与者不可计数和进程重启丢失晋升证据问题。

这不表示生产 Shadow 已获准启动。受保护环境仍需另行创建并审核最终 run manifest、私有
目录、Provider、部署提交、参与者分配、停线与回滚；30 个有效 case 尚未采集，D10 结果
尚不存在。
