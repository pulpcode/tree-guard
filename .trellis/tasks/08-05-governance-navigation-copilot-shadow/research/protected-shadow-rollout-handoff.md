# 受保护环境生产 Shadow 交接方案

## 目的与边界

本方案把已验证的仓库实现交给受保护环境做首轮真实工作流 Shadow。外网任务只冻结通用
流程、固定阈值和公开提交，不记录真实信息树、真实请求、内部资源/版本、参与者身份、模型
流量、sidecar 路径或网络配置。

- 部署基线：`e3c27de768e2c16c5e18369482507f1bc5db988f`；
- 推荐 Provider：`QWEN_LIVE`，不得自动回退到百炼或仿真；
- feature flag 缺省关闭；
- 只读信息树、人工最终导航、私有 sidecar；
- 不修改生产树、数据库或 Patch，不产生 Gold 或语义批准。

## 推荐分母

- 正式 run 预注册 `planned_case_count=36`；
- 3 名参与者使用运行内匿名编号 `P01/P02/P03`，每人计划完成 12 个终态 case；
- 至少 30 个 case 必须属于可判断终态；`UNKNOWN` 和 `EXITED` 保留在完整记录中，但不进入
  有效分母；
- 36 个计划 case 必须全部终结并生成资格记录后才能判断门槛，不能看到中间结果后提前停止；
- 正式 run 前可安排每人最多 2 个练习 case，但必须使用不同 run/root，不能混入正式分母。

参与者匿名编号与真实人员的映射只留在受保护环境的访问控制材料中，不进入 manifest 的
外传副本、API、聚合或本仓库。

## 启用前冻结

受保护环境负责人逐项确认：

1. 实际部署字节来自上述提交，`TREEGUARD_WORKBENCH_BUILD_COMMIT` 精确匹配；
2. run manifest 使用 `QWEN_LIVE`、36 个计划 case、3 个匿名参与者和代码内固定 D10 阈值；
3. 每名参与者使用独立 Workbench 实例和独立 `0700` sidecar 根目录；
4. manifest 与聚合输出父目录为当前运行用户所有的 `0700` 目录，文件为 `0600`；
5. 正式资源、版本和允许使用范围另在受保护环境冻结；不得在本仓库记录这些值；
6. 模型端点、只读仓库、访问控制、启动方式和回滚负责人已由内网审核；
7. diagnostics 缺省关闭；若临时开启，只允许本机内存查看且不得截图、复制或外传；
8. 正式 run 的计数起点、结束条件和 sidecar 根目录在第一个 case 前确定。

## 单 case 操作

1. 参与者用自然工作语言提出一个当前确有价值的导航需求；不要求先选中节点；
2. 系统最多进行一次澄清并展示最多 8 个候选；
3. 参与者确认候选、使用候选外节点纠正，或明确选择：
   - 树中有目标但未找到；
   - 树中没有对应节点；
   - 暂时无法判断；
   - 退出本次；
4. 一个 case 只能有一个终态；后续新需求必须新建 case；
5. 不要求参与者为了“帮助模型”改写成节点原名；自然失败应被保留。

## 立即停线

发生任一情况立即把 feature flag 设回 `0` 并停止新增 case：

- 任何生产树、数据库、治理表单或 Patch 写入；
- 树快照、部署提交、Provider、run 或参与者绑定失败；
- sidecar 目录/文件权限不合格、资格记录缺失、重复 outcome、篡改或超出计划数；
- 模型调用突破单 case 两个逻辑阶段，或发生未获批准的 Provider 回退；
- API/页面/普通日志暴露请求正文、稳定节点 ID、模型流量、内部路径、hash 或参与者映射；
- 失败影响既有只读 Workbench 或生产业务状态。

模型超时、合同失败或候选为空本身不必停线，只要既有安全降级完整生效；这些 case 按真实
终态进入分母或无效计数。

## 汇总与判定

完成精确 36 个终态 case 后，在受保护环境使用冻结 manifest 和三个 sidecar 根目录运行
`treeguard-navigation-shadow aggregate`。只有同时满足以下条件才返回
`EXPANSION_ELIGIBLE`：

- 至少 30 个有效 case、至少 3 名有效参与者；
- 安全终止、快照绑定、零生产写入均为 100%；
- 目标存在 case 的初始 Top-8 覆盖不低于 80%；
- 目标存在 case 的人工导航完成率不低于 90%；
- 强证据候选的人工否定/纠正率不高于 5%；
- 已完成导航 case 的中位耗时不超过 3 分钟。

`HOLD_NOT_QUALIFIED` 只说明当前路径不应扩围；不得在同一 run 内修改 Prompt、Top-K、阈值、
参与者或分母后重算。需要优化时结束本 run，形成只含固定错误码和聚合计数的诊断，再以新
提交、新 manifest 和新 run 重新预注册。

## 回滚与证据保留

回滚动作固定为关闭 feature flag 并重启对应 Workbench 实例；不删除或改写已发布的私有
sidecar。保留的受保护证据包括最终 manifest、资格 sidecar、聚合文件、部署提交核验和内网
审核记录。外网只允许接收经过正向允许列表和人工批准的固定状态与聚合统计。

即使结果为 `EXPANSION_ELIGIBLE`，也只允许进入下一轮 Shadow 扩围审核，不授予自动绑定、
生产写入、Gold、Patch 或模型自治资格。
