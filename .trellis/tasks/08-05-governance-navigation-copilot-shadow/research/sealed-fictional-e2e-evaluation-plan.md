# 导航 Copilot 密封虚拟树端到端测评计划（草案）

## 目的与结论边界

本测评位于外网确定性回归与受保护环境生产 Shadow 之间，回答三个问题：

1. 最新完整链路在未参与开发调参的虚拟树上，能否把自然语言需求恢复为可用 Top-8；
2. 理解软信号和 Semantic 比较是在帮助、无效还是伤害最终候选与高亮；
3. 失败能否准确归因到理解合同、宽召回、Semantic、Policy 或交互，而不是只得到“运行成功”。

通过只表示具备进入受保护环境小范围 Shadow 的资格，不证明生产效果、Gold、专家共识、
自动绑定、生产写入或 Patch 资格。

## 总体设计

采用两层数据，不能用已揭盲数据直接给出最终结论：

- **开发冒烟层**：复用现有完全虚构树和既有场景，只验证 runner、Provider、私有 IO、
  Oracle 隔离和归因代码；结果不进入晋升分母；
- **密封资格层**：使用一棵新建的 clean-room 虚构 resource 树、全新自然语言需求和隐藏
  Oracle；数据提交、功能提交、模型配置和门槛冻结后只执行一次。

现有 H1/H2、M4/M5、M4.9、R2 与青岚场景均已参与生成、审核、实验或调试，只可用于
回归。即使某个保留场景没有正式执行，只要请求或 Oracle 已提交并被审阅，也不再属于未见
资格分母。

## 被测系统

测评必须走当前真实产品纵切，不另写简化版理解或召回算法：

```text
虚构树 + 自然语言需求
→ Workbench Navigation Copilot HTTP API
→ BAILIAN_LIVE 理解
→ 原文宽召回 + 角色/上下文软重排
→ BAILIAN_LIVE relation-only Semantic
→ 本地确定性 Policy
→ Oracle 驱动的受控人工动作
→ 私有 sidecar
→ 独立确定性评分器
```

- 外网资格运行固定为 `BAILIAN_LIVE`，不自动回退到 Simulator 或 Qwen；
- `SIMULATOR_LIVE` 只做执行前协议冒烟；
- 每个 case 沿用最多两个逻辑模型阶段；Provider 合同内纠错重试单独记账；
- 功能提交、数据提交、Prompt 版本、模型名、endpoint 类别、计划 case 数、重复子集和门槛
  必须在首次真实调用前冻结；
- 原始请求、模型请求/响应和逐项结果只进入 `0600` 私有工件，不进入 Git 或公开报告。

现有生产 `NavigationShadowQualification` 只用于真实用户 Shadow 记账，不能充当本测评
Oracle。其部分安全字段来自运行合同常量，直接复用会让安全率形成天然 100% 的恒等式。
本测评必须使用独立 evaluation manifest、Oracle、逐阶段 scorer 和聚合 Schema。

## 新虚拟树要求

- 规模建议 700—1,000 个节点，贴近当前常见生产规模而不制造无业务意义的超大压力树；
- 仅含 resource Schema，`VALUE` envelope 为 0；
- `CLEANROOM_SYNTHETIC / fictional=true / derived_from_real=false`；
- 6—10 个语义连贯的顶层分支，深度 4—6，包含同层近邻、跨分支近义、类型/基数冲突和
  多个可接受目标；
- 不使用“维度列表 × 指标列表”的笛卡尔积扩充节点；每个子树由独立业务蓝图生成，节点
  必须有明确父子语义；
- 不读取既有场景正文、隐藏 Oracle、逐项模型结果或 Prompt；不得运行被测 Copilot 来选择
  哪些需求进入冻结集。

树、公开 scenario 与隐藏 Oracle 物理分离。Oracle 不能进入模型投影、公开 manifest、
Workbench API 或公开 aggregate。

## 样本分母

最多准备 56 条候选，经 Codex 进行自然性和 Oracle 一致性 Silver 审核后，冻结精确 48 条：

| 类别 | 数量 | 主要目的 |
|---|---:|---|
| 字面唯一目标 | 10 | 验证基本候选恢复与唯一高亮 |
| 非字面唯一目标 | 10 | 同义、缩写、口语目的、轻微错别字、跨层表达各 2 条 |
| 结构干扰 | 8 | 同层近邻、跨分支近义、节点种类冲突、值类型/基数冲突 |
| 多个可接受目标 | 4 | 验证多等价目标不被伪装成唯一真值 |
| 合法澄清 | 6 | 验证第一次提问、冻结回答、重新理解和跳过 Semantic |
| 弱证据目标 | 4 | 验证目标仍可见但系统安全进入 `NEED_EVIDENCE` |
| 树中无目标 | 6 | 验证 `NONE/NEED_EVIDENCE`，禁止错误强推荐 |

前 42 条构成“树中存在目标”的 Top-8 分母，最后 6 条只进入空目标和错误自信分母。
另外预先给 8 条目标存在 case 添加错误或无关页面上下文标签；它们仍计入原类别，不另增
分母。多标签不能改变上述主类别配额。

## 隐藏 Oracle 最小合同

每条 Oracle 至少绑定：

- scenario 引用、树 digest、请求字节 digest 和主类别；
- `PROCEED / CLARIFY / LIMIT` 期望路线，以及有明确结构事实时的可接受四字段 profiles；
- `TARGET_PRESENT / TARGET_ABSENT`；
- 一个或多个可接受稳定 node ID；空目标时必须为空；
- 明确禁止作为正确答案的结构干扰 node ID，可为空；
- `CLARIFICATION_REQUIRED / NOT_APPLICABLE`；
- 合法澄清 case 的冻结回答；
- 可接受的最终 Policy 状态集合；
- 可接受的 `(outcome action, target node, target disposition)` 联合元组；
- 页面上下文策略和是否预期为错误上下文压力项；
- Silver 审核状态、受审字节 digest、执行资格和非 Gold/非 Patch 声明。

不强迫 Oracle 为四字段理解规定唯一文本答案。`node_kind/value_type/cardinality` 只在需求有
明确结构事实时给出可接受 profile；`UNKNOWN/null` 在证据不足时可以合法。理解阶段主要按
合同成功、是否错误澄清、来源绑定和对 Top-8 的实际影响评分。

## 受控人工动作

主指标不能依赖评测人员临场选择。runner 使用隐藏 Oracle 模拟一致的“理想审核者”：

- 可接受目标在 Top-8：选择排名最高的可接受目标；
- 目标存在但未进入 Top-8：走候选外纠正，并严格记为 Retrieval miss；
- 目标不存在：拒绝全部并记录 `TARGET_ABSENT`；
- 合法澄清：第一次模型提问后送入冻结回答，再继续现有 D11 路径；
- 模型不该澄清却提问、该澄清却未提问或问题与冻结回答明显不相容，记录独立澄清 finding，
  不把后续偶然命中改写为澄清正确。

澄清问题的语义相关性和候选差异说明质量由预先选定的 Silver 审核子集补充判断，不覆盖
确定性主指标。

## 对照与阶段指标

同一冻结请求同时计算两个候选视图：

- **R0 原文保底**：理解强制降级，只用原始需求和可信显式提示做确定性宽召回；
- **C1 完整链路**：真实理解软信号、软重排、Semantic 和 Policy。

R0 不增加模型调用，也不参与用户动作，只用来回答模型软信号对 Top-8 的净影响。

| 阶段 | 主指标 | 失败归因 |
|---|---|---|
| 理解 | 合同成功率、必要/无谓澄清、降级率 | `UNDERSTANDING` |
| 召回 | Recall@8、MRR@8、R0→C1 帮助/伤害数、错误上下文子集 | `RETRIEVAL` |
| Semantic | 正确高亮精度、多等价识别、空目标错误强推荐 | `SEMANTIC` |
| Policy | 期望状态集合命中、降级状态正确性 | `POLICY` |
| 端到端 | 候选内完成、候选外纠正、终态完整性 | `END_TO_END` |
| 稳定性 | 候选目标可见性与 Policy 状态的 2/3 一致 | `REPEATABILITY` |

“候选外纠正后完成”只计产品可恢复，不计召回命中；“没有突出任何候选”不能自动得到高
精度，必须同时报告正确高亮覆盖率和 `NEED_EVIDENCE` 比例。

主分母始终是全部 48 条预注册 case。未运行、Provider 失败、合同失败或没有产生终态均按
对应阶段失败记账，不能从分母中删除。重复轮、扰动副本和同模板变体按原 scenario family
聚合，不增加独立样本量。

## 执行顺序

1. **合同冻结**：冻结数据 Schema、Oracle、分母、门槛、功能提交、模型配置和最大调用数；
2. **独立造数**：在单独 worktree/对话中构造新树和最多 56 个候选，不运行当前链路；
3. **Silver 审核**：Codex 审核自然性、目标可回答性、唯一/多目标/空目标和 Oracle 一致性，
   最多两轮修改；冻结 48 条后不再热修；
4. **确定性 preflight**：校验来源、节点数、0 VALUE、配额、Oracle 隔离、hash、权限、模型
   输入 canary 和 R0 可回放；
5. **协议冒烟**：用 Simulator 跑不进入分母的固定少量 case，只验证完整 HTTP/sidecar；
6. **主运行**：48 条各运行一次 C1，观察结果前不得替补、改 Prompt、调排序或改门槛；
7. **稳定性运行**：预注册 16 条挑战子集，分别从非字面、结构干扰、澄清、弱证据各取 4
   条，再额外运行两轮；稳定性结果不改变主运行分母；
8. **确定性评分**：先对 R0/C1、Oracle 和逐阶段工件评分，再生成只含固定 code 和聚合计数
   的公开报告；
9. **Silver 质检**：预注册 12 条分层样本，审核澄清问题和差异说明是否有用，只作为辅助
   证据；
10. **一次性判定**：输出资格状态；若失败，该密封集转为开发回归集，后续晋升必须使用新
    密封分母，不能在同一 48 条上循环调优后重新宣称未见通过。

主运行和稳定性运行最多 80 个逻辑 case；每个最多两个逻辑模型阶段，因此逻辑模型调用上限
为 160。Provider 合同内的纠错重试单独计数并在 manifest 中冻结 wire attempt 上限。

## 推荐预注册门槛

### 硬门槛

- 48/48 来源、树快照、Oracle、sidecar 和结果可严格回放；
- Oracle、稳定目标 ID、Prompt、模型原始流量和逐项结果零公开泄漏；
- 48/48 单 case 逻辑模型阶段不超过 2，零隐式 Provider 回退；
- 48/48 产生唯一终态，零生产树、数据库、Gold 或 Patch 写入；
- 任何分母、配置、模型、Prompt、树或 Oracle 漂移立即判定 `DATA_OR_RUN_INVALID`。

### 能力门槛

- 目标存在 42 条中，C1 Top-8 至少命中 36 条（不低于 85%）；
- 目标存在 42 条中，内部 Top-40 至少命中 38 条（不低于 90%），用于区分宽召回漏失与
  Top-8 压缩失败；
- 非字面至少 8/10、结构干扰至少 6/8、澄清后至少 5/6 的目标进入 Top-8；
- 8 条错误/无关上下文压力项至少 7 条保持目标进入 Top-8；
- 6 条空目标中错误强推荐为 0；
- 所有 `CANDIDATES_AVAILABLE` 高亮中，正确目标比例不低于 95%，且不能以极少高亮规避，
  正确高亮至少覆盖 42 条目标存在 case 的一半；
- 无模型降级完成完整预期路径的 case 至少 44/48；
- 期望路线、Policy 状态和受控 outcome 联合匹配至少 41/48；合法澄清至少 5/6 被提出，
  其余 42 条非澄清 case 中无谓澄清不超过 4 条；
- C1 Top-8 总命中不得比 R0 原文保底少 2 条或更多；每个伤害 case 单独归因；
- 稳定性子集至少 14/16 在三轮中有不少于两轮保持相同的目标可见性和 Policy 状态；重复
  运行中空目标错误强推荐仍为 0。

门槛按整数计数实现，比例只用于展示，避免浮点边界和小分母误读。中位操作耗时仍记录，
但虚拟 runner 的自动动作不能替代生产 D10 的真实用户三分钟指标，因此不作为本轮资格
硬门。

## 判定状态

- `READY_FOR_PROTECTED_SHADOW`：硬门槛和能力门槛全部满足；
- `HOLD_RETRIEVAL`：目标可见性或错误上下文门槛失败；
- `HOLD_SEMANTIC_POLICY`：召回达标但高亮、歧义或空目标判断失败；
- `HOLD_MODEL_CONTRACT`：模型合同/降级率未达标；
- `DATA_OR_RUN_INVALID`：来源、隔离、冻结、回放、分母或安全合同失败；
- `INCONCLUSIVE`：运行未完成冻结分母，不允许部分样本推断。

只有第一种状态允许进入受保护环境首轮生产 Shadow 审核；它仍不允许默认启用或自动写入。

## 实现分工建议

功能分支只新增测评合同与 runner，不修改当前 Copilot、Provider、召回、Prompt 或 UI：

- `src/treeguard/navigation_copilot_sealed_validation.py`：Oracle、逐阶段评分、聚合和判定；
- `scripts/run_navigation_copilot_sealed_eval.py`：通过真实 Workbench API 驱动 R0/C1 和受控
  outcome；
- 版本化 evaluation manifest/result Schema；
- 聚焦测试覆盖 Oracle canary、分母、篡改、阶段归因、重复性、私有 IO 和公开聚合。

数据分支独立拥有新树、scenario、Oracle、审核和 preflight。功能与数据以冻结 Schema 和
提交 hash 交接，不共享逐项运行结果。数据完成前可并行实现合同，但任何真实模型运行必须
等两边分别提交并冻结。

## 已接受方案

有三种可行强度：

1. **MVP 硬门（推荐）**：全新 clean-room 树、48 条主分母、16 条预注册挑战子集额外两
   轮；成本可控，同时具备树级未见和局部重复性证据；
2. **强化硬门**：全新树、60 条独立 family 全量运行三轮；统计更稳定，但数据审核和模型
   调用成本约为推荐方案的两倍以上；
3. **诊断方案**：复用现有树，只生成新请求；成本最低，但不能声称树级未见泛化，也不应
   阻断或批准生产 Shadow。

已接受方案 1，并把它作为生产 Shadow 的硬前置门。方案 2 保留为未来强化选项；方案 3
只可用于诊断，不得替代本轮资格结论。
