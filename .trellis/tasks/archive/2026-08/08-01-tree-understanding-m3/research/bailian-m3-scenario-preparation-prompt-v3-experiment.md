# M3 Prompt v3 百炼 312 节点虚构树合同复验

## 范围与数据边界

- 日期：2026-08-02；
- 模型：`qwen3.6-35b-a3b`；
- 数据：仓库内独立构造的 312 节点青岚完全虚构树和 M3 新节点 overlay；
- 计划：13 个确定性单元，包括 8 个风险挑战和 5 个分支覆盖单元；
- 用途：验证 Prompt v3 的精确请求执行、首发合同遵循、条件重试、批次归并和
  已知机械文本缺陷 canary；
- 记录边界：批准清单、哈希、端点、Prompt、请求正文、原始响应和候选文本均不写
  入仓库；运行器只在内存中校验候选，本文只保存聚合指标和固定错误码。

## 独立语义审核复验

经单独批准后，相同 Prompt v3 请求集又执行一次语义取样。运行时只把本地合同解析
后的候选草稿短期写入权限为 `0600` 的私有临时工件，没有保存原始响应 envelope；
完整批次生成后才打开隐藏参照，隐藏参照只用于检查风险方向，不作为 Gold。第二次
运行的 transport 聚合如下：

| 指标 | 第二次运行 |
|---|---:|
| 实际 HTTP 尝试 | 14 / 26 上限 |
| 首发 / 合同失败重试 | 13 / 1 |
| 首发通过 | 12 / 13 |
| 重试通过 | 1 / 1 |
| 正常结束 / `finish_reason=stop` | 14 / 14 |
| Prompt / Completion tokens | 59,457 / 4,572 |
| 总 tokens | 64,029 |
| 最终候选 / 失败 / 未执行 | 13 / 0 / 0 |
| 批次状态 | `SUCCESS` |
| 投影节点覆盖 | 238 / 312（76.3%） |

一次首发因 `SCENARIO_PREPARATION_MODEL_TEXT_POLICY_INVALID` 被本地合同拒绝，对应
的已批准条件重试随后通过。Prompt v3 两次运行分别为 `13 / 13` 和 `12 / 13`
首发通过，但最终均得到 `13 / 13` 合同候选；这再次说明即使请求声明温度为零，也
不能把远端模型视为逐次严格可重复。

审核沿用 v1/v2 每项 0--2 分的五维 rubric。13 个候选的聚合评分如下；评分只用于
比较候选质量，不构成专家裁决、Gold 或 MVP 验证结论：

| 维度 | Prompt v1 | Prompt v2 | Prompt v3 |
|---|---:|---:|---:|
| 清晰性 | 14 / 24 | 23 / 26 | 25 / 26 |
| 可执行性 | 10 / 24 | 18 / 26 | 25 / 26 |
| 证据关联 | 15 / 24 | 20 / 26 | 21 / 26 |
| 风险族与目标区分 | 16 / 24 | 21 / 26 | 21 / 26 |
| 不过度声称 | 12 / 24 | 14 / 26 | 14 / 26 |
| 合计 | 67 / 120 | 96 / 130 | 106 / 130 |

| 分级 | Prompt v1 | Prompt v2 | Prompt v3 |
|---|---:|---:|---:|
| 可原样进入后续人工筛选 | 3 / 12 | 3 / 13 | 5 / 13 |
| 语义方向可保留但必须修订 | 4 / 12 | 8 / 13 | 7 / 13 |
| 拒绝 | 5 / 12 | 2 / 13 | 1 / 13 |
| 无候选 | 1 / 13 | 0 / 13 | 0 / 13 |

Prompt v3 本次平均 rubric 得分约为 81.5%，高于 v2 的约 73.8%；可原样进入人工
筛选的候选由 3 条增加到 5 条，拒绝由 2 条减少到 1 条。8 个风险挑战单元中为
3 条可筛选、4 条需修订、1 条拒绝；5 个分支覆盖单元中为 2 条可筛选、3 条需
修订、0 条拒绝。由于各版本都只有一轮小样本语义取样，且远端生成不严格可重复，
这些差异只能视为当前样本中的方向性证据，不能作显著性或生产稳定性结论。

本轮正向表现主要包括：新增节点的自然语言数量表达与锁定基数一致；同名澄清保留
了两个上下文；证据不足候选具体说明了仍需的业务输入；无界组合把过宽诉求保留在
需求中，并只在不确定性中提出收敛建议。主要剩余缺陷为：

1. 冲突类候选仍会在理由中替有意冲突的父节点或节点种类补写“更符合实际”等未经
   树证据支持的业务判断；“不过度声称”维度与 v2 相同，仍是最弱项；
2. 个别候选从一个锚点扩展到多个相邻结构要素，但所报支持引用没有覆盖全部诉求，
   因此机械引用合法不等于需求—证据实质完整；
3. 一个基数冲突候选把冲突转移到未由支持引用覆盖的相邻字段组合，没有准确表达
   指定锚点的单值/多值冲突，因而应拒绝；
4. 两个已有节点复用候选仍把结构字段写成“指定具体值”的请求方向。它们没有声称
   树中已经存在实例值，但仍需人工改写回字段定义诉求；
5. 自然语言字段中的临时投影引用、模板哨兵、基数必填误释和完全重复文本均为零，
   说明 v3 的确定性文本门禁有效，但这些机械 canary 不能替代上述语义审核。

## 限制与下一步

1. 当前结果证明的是 13 单元有界计划可以稳定地产生合同候选，以及 v3 在本次小
   样本中提高了候选可用度；不能证明模型理解未投影的 74 个节点、整棵树或生产领域；
2. 候选仍全部是 `PENDING_HUMAN_REVIEW`，不能自动注册到
   `ValidationDatasetProvider`，也不能成为 Oracle、Gold、Patch 或生产写入依据；
3. 下一步若继续优化 Prompt，应优先约束理由中的业务背书、单锚点到多字段的证据
   扩张，以及已有节点复用中的结构/实例措辞；不应以宽泛中文关键词门禁冒充语义
   校验；
4. 若要判断 v3 是否稳定优于 v2，应在新批准下增加多个独立领域或树形状、重复运行
   和盲审，而不是继续在同一 13 条样本上迭代到过拟合；
5. 本轮私有候选工件在上述聚合结论写入后删除；仓库继续不保存模型生成正文、请求、
   响应 envelope、批准载荷、端点或凭据。
