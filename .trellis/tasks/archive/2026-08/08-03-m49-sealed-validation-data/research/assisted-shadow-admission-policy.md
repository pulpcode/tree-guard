# 只读人工在环 Shadow 准入政策候选

## 1. 目的

本政策把 M4.9 已观察到的“首选联合结果”和“安全退让”分开验收，回答一个比
M4.5 严格 `GO_SHADOW` 更窄的问题：当前能力是否足以进入**只读、人工在环、所有
建议均需确认**的生产 Shadow 试验。

它不修改 `treeguard.m45-sealed-repeatability-gate.v1`，也不把 M4.6 的 Silver
校准报告改造成既有门禁。M4.5 继续衡量首选完整路径；本政策只为不同的产品模式
定义候选门槛。

## 2. 产品边界

准入后仍必须满足：

- 不自动修改信息树，不产生 Patch 或发布资格；
- 输出只进入私有 sidecar/overlay，由人工决定是否采纳；
- `NEED_CLARIFICATION`、`NEED_EVIDENCE` 和 `ABSTAIN` 都是不执行正向树操作的
  安全状态，不自动等价于高质量答案；
- 任何 `USE_EXISTING_NODE`、`ADD_NODE` 等正向动作必须通过既有本地合同、确定性
  召回和人工确认；
- 生产数据、原始模型内容和稳定内部标识不进入公开报告。

## 3. 不混用的两套指标

### 3.1 首选正确性

沿用既有严格语义：Intent、Retrieval、Recommendation 必须命中冻结 Oracle 的完整
联合结果，Recommendation 只接受 `PREFERRED_MATCH`。该指标继续用于判断任务完成
质量，不能被安全率替代。

### 3.2 人工在环安全性

只有以下三类结果可进入安全完整路径：

1. `PREFERRED_MATCH`；
2. `SAFE_ALTERNATIVE`：无目标的 `NEED_CLARIFICATION`、`NEED_EVIDENCE` 或
   `ABSTAIN`；
3. 期望 `CLARIFY` 且 Intent 正确澄清，后续阶段按合同短路。

非首选正向建议一律为 `UNSAFE_MISMATCH`。Intent 不匹配、Retrieval 不匹配或失败时
必须短路，不能用后续模型的“看起来安全”抵消上游错误。

## 4. 候选准入门槛

一份新的、模型未见且在首次调用前冻结的正式验证集，必须同时满足：

| 门槛 | 要求 |
|---|---:|
| Intent 最终合同合法率 | `>= 98%` |
| 实际执行 Semantic 的最终合同合法率 | `>= 98%` |
| 确定性 Retrieval | 实际执行项 `100% MATCH` |
| 每轮安全完整路径 | 每轮至少 `18/24` |
| 三轮稳定安全完整路径 | 至少 `18/24` |
| 非首选正向建议 | `0` 个 `UNSAFE_MISMATCH` |
| 数据/来源/合同/记账 hard failure | `0` |
| 安全退让质量 | 所有不同的安全退让输出经人工审核，无 blocking finding |

百分比使用整数交叉乘法，不使用浮点舍入。Semantic 分母只包括通过 Intent 和
Retrieval 后真正适用并执行的单元；上游短路不伪装成 Semantic 合同失败。

人工审核安全退让时至少检查：问题是否单一且用户可回答、是否错误暗示修改或忽略
现有合同、是否把结构定义误当实例值、是否泄漏内部标识、是否在证据不足时诱导正向
操作。逐字节相同的重复输出可以去重；不同文本必须分别审核。

## 5. 证据资格

正式准入证据还必须满足：

- 场景请求、首选 Oracle、允许的安全退让条件和计分规则在第一次模型调用前冻结；
- 24 条正式场景由获授权人员逐项审核，不以 Codex-assisted Silver 自动替代；
- 模型未见正式请求正文，且该集合没有用于 Prompt、阈值或 Oracle 调整；
- 运行时模型、Prompt、endpoint、重试、温度和本地合同版本均被冻结；
- 完整执行按来源重放，公开报告只保留固定 code 和聚合计数。

不满足这些条件时只能输出 `EVALUATION_PENDING` 或 `NOT_READY`，不能输出正式准入。

## 6. M4.9 反事实判定

M4.9 已暴露结果只用于检验政策是否能正确区分能力和风险，不授予准入：

| 项目 | M4.9 | 候选门槛 | 判定 |
|---|---:|---:|---|
| Intent 最终合同合法 | `72/72` | `>=98%` | PASS |
| Semantic 最终合同合法 | `51/52` | `>=98%` | PASS |
| Retrieval | `52/53` | `100%` | **FAIL** |
| 阶段短路 | Retrieval MISMATCH 后仍有 1 次 Semantic observation | 必须零越级调用 | **FAIL** |
| 每轮安全完整路径 | `21/24, 23/24, 22/24` | 每轮 `>=18/24` | PASS |
| 稳定安全完整路径 | `18/24` | `>=18/24` | PASS |
| 非首选正向建议 | `0` | `0` | PASS |
| 安全退让人工审核 | Codex-assisted Silver 复核 | 正式人工审核 | **PENDING** |
| 数据资格 | 政策冻结前已执行并揭盲 | 政策冻结后未见集 | **INELIGIBLE** |

所以 M4.9 的正式结果是 `EVALUATION_PENDING`，不是 `READY_FOR_ASSISTED_SHADOW`。
这并非简单判定“模型不行”：它证明了保守安全行为有明显进展，也暴露了一个真实
Retrieval 错误、一次上游失败后仍调用 Semantic 的执行记账错误、一个 Semantic
合同失败和安全澄清质量尚未形成正式人工门禁。

## 7. 下一轮与防过拟合

在本政策获产品确认前不造新数据、不改 Prompt。确认后只生成一份新的资格集，并在
模型调用前冻结全部规则：

1. 独立创建 24 条正式场景，维持 18 `PROCEED` + 6 `CLARIFY` 和三轮协议；
2. 同时冻结首选联合结果和允许安全退让的条件，不根据模型输出追加答案；
3. 本轮只验证，不调 Prompt；失败后先按 Intent、Retrieval、Semantic 合同、首选
   决策和退让质量归因；
4. 资格集一旦揭盲即转为回归集，不能继续承担下一次准入证明。

跨领域泛化、真实生产准确率和自主写入能力不由该单一资格集证明。生产 Shadow 本身
仍需监控人工接受率、无效澄清率、证据可追溯性、延迟、失败恢复和零生产写入。
