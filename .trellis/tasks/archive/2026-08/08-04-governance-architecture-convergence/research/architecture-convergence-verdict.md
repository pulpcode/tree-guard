## 已接受的架构决策

### D1：权威查询来源

保留既有 D1：原始 `requirement_text` 是权威主查询；本地可校验的结构提示和可选界面
上下文只能提供软信号。模型摘要、假设、证据缺口和澄清文本不成为主查询真值。

### D2：source-bound 角色提议独立于 Intent

`RetrievalRoleEvidence` 单独绑定原始请求字节中的
`TARGET / SCOPE / EXCLUSION`。`source-bound` 只证明 span 的指定区间与原文一致并可
确定性排序和回放，不证明该文本在全文唯一，也不证明角色语义分类正确。当前构造器会
额外拒绝无法唯一定位的提议文本，但持久化合同只按明确的 `start/end` 复核原文切片。

模型产生的角色结果固定视为 `UNVERIFIED_MODEL_CALIBRATION` 提议；Codex/Silver 角色
标注也只是非 Gold 的开发期校准。原始 `requirement_text` 始终保留为权威输入。角色
提议可以贡献有界加权和解释，但不得单独硬裁剪由原始需求得到的宽候选，不得被称为业务
事实，也不得授权动作。角色提议与 StructuralIntent 是否合并在一次调用中只是一项可选
的时延/成本实验；无论调用形态如何，两者都必须分别由本地合同验证。

这是目标架构边界，不表示当前 R1 的 exact TARGET gate 已满足该边界；该 gate 只保留为
实验实现，不得晋升为默认产品路径。

### D3：Semantic 只判关系，本地 Policy 选动作

Semantic 只负责受控候选上的逐项关系和证据充分性。本地确定性 Policy 负责目标选择、
动作、空目标和安全降级。多个等价候选进入澄清；缺少等价证据时退让。
`REUSES_CONTRACT` 和 `CONTEXTUALLY_RELATED` 暂不授予自动新增权限。

### D4：StructuralIntent 固定四键，不强制模型给出确定值

下一版本机器决策合同固定序列化四个键：`node_kind`、`value_type`、`cardinality`、
`clarification_question`；它们构成当前证据支持的最大机器语义面。四键始终存在以服务
Schema 和回放，但不表示每次请求都必须让模型一次性给出四个确定值。取值优先级冻结为：

1. 用户在请求中明确给出的结构提示，经本地校验后优先；随手点击的当前节点不属于此类，
   仍只是低信任软上下文；
2. 能由确定性规则从可信输入直接得出的字段由本地生成；
3. 只有下游确实需要且前两项缺失时，模型才提议缺失字段；
4. 证据不足时保留 `UNKNOWN` 或 `null`，不得为了输出确定值而猜测。

检索前的 `clarification_question` 只处理请求文本自身存在、且会改变结构意图的歧义；
只有比较真实树候选后才暴露的歧义，留到 D3/D6 的候选比较阶段处理。固定四键可以服务
Schema、回放和兼容，但结构字段与角色是否合并在一次模型调用中只是待 A/B 的实现选择，
不是冻结的必要条件。当前隔离 v2 只证明合同、来源绑定和篡改门禁可实现，尚未证明该
调用形态在 live、未见或生产数据上的能力。

### D5：Retrieval 是候选发现层，不是语义裁决层

- Retrieval 只负责提供可回放的宽候选和证据，不把 Top-1 或排序分数当作业务真值；
- R2 lexical 保留为当前开发基线和可解释 lexical leg，不宣称 Shadow 或生产资格；
- H1、H2 保留为实验实现和负向证据，不进入默认产品路径；
- `proposed_parent`、当前页面或选中节点只可软加权，不得硬裁剪全树；
- 模型角色提议不得成为唯一硬过滤条件；必须保留从原始需求恢复宽候选的路径；
- 没有通过开发门槛的候选时，不准备其未见资格集，也不以 Semantic 掩盖召回缺失。

### D6：下一产品目标收缩为治理/导航 Copilot

下一产品纵切不再以“任意自由文本自动绑定唯一节点”为成功定义，而是：

1. 给出有界候选及其路径、结构和语义差异；
2. 能安全返回 `AMBIGUOUS`、`NONE` 或证据不足；
3. 必要时提出一个高区分度问题，单轮仍不能解决时交给人工审查；
4. 人工保留最终选择权，反馈只作为运营记录；
5. 不自动修改信息树，不形成 Gold、语义批准或 Patch 资格。

这是一项新的产品假设，不是 H2 的重试，也不是当前任务中的新实现切片。

## 明确关闭的路径

- 不在 H2 的28条已揭盲数据上更换模型、instruction、pooling、权重、维度、量化、
  RRF、窗口或 reranker；
- 不启动只改变 embedding 型号或 Prompt 的 H3；
- 不把全树 Top-1 自动精确绑定作为当前 Shadow MVP；
- 不把界面选中节点作为必要前提或硬路由条件；
- 不把新一批同类合成数据当作生产泛化证据；
- 不因为候选缺失而授权新增节点或让 Semantic 伪装成已完成判断。

若未来重新探索召回，必须同时满足：一个可归因的单一变量假设、独立开发分母，以及
能够说明该变化服务于已冻结产品目标的实验合同。只有替换模型、Prompt、Top-K 或新造
相似数据，不构成重新开启理由。

## 原验收门槛的处置

原 PRD 要求候选方案改善预注册召回主指标。H1 与 H2 均未满足，因此该项结果保持
`FAILED`，不能改写为 `PASS`。

本判定已经项目负责人接受。当前任务可在工作提交完成后按研究型负结果
`COMPLETED_WITH_NO_QUALIFIED_RETRIEVAL_CANDIDATE` 关闭。这里的 `COMPLETED` 仅表示
预注册实验、失败归因和架构选择工作已经完成，不表示模型、召回、v2 纵切、Shadow 或
生产验收通过。

## 下一任务的进入条件

新的治理/导航 Copilot Shadow 任务应另立 PRD，并在实现前冻结：

- 输入是否只有原始需求，还是还包括可选页面/流程上下文；
- 候选上限、差异解释、`AMBIGUOUS/NONE` 和单轮澄清合同；
- 人工选择、修订、拒绝和退出的状态机；
- 候选接受率、纠正率、错误自信率、澄清次数、审查耗时和证据覆盖等指标；
- 真实内网 Shadow 数据只留在受保护环境，外网只接收经批准的合同和聚合结果；
- 完全虚构数据只承担回归和工程验证，不单独产生生产资格。

在该新任务通过规划审核之前，现有 v1 默认入口保持不变，隔离 v2、H1 和 H2 均不晋升。

## 结论限制

- 本判定不证明所有向量召回均不可行；
- 不证明 LLM 完全不能理解信息树；
- 不证明 R2 lexical 已足以进入生产；
- 不证明 relation-only Semantic 已经达到未见或生产准确率；
- 不使用跨项目实验记录替代本项目资格证据；跨项目比较只用于提高路线风险判断。
