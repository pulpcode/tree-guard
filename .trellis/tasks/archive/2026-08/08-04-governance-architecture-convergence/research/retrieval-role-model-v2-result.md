# Retrieval 角色模型 v2 首次冻结结果

## 结果

- 模型与调用：`qwen3.6-35b-a3b`，v2，18次首发，0重试，0传输失败；
- 合同通过：18/18；
- Silver exact case：8/18；
- 模型 span 38、Silver 29、匹配27；precision 0.710526、recall 0.931034；
- 漏失2个，全部为 TARGET，且都被同角色模型 super-span 替代；
- 额外11个：TARGET 4、SCOPE 2、EXCLUSION 5；
- 五视图均为 Recall@8/20=14/16、MRR=0.875、空目标2/2、重放18/18；
- 总体：FAIL。

## 与 v1 比较

v2 的最小完整名词短语规则没有修复两个稳定的 TARGET super-span。核心下游指标与
v1 两次运行完全相同，而额外 span 增多、exact case 和 precision 下降。因此不存在
继续 v3 Prompt 的证据。

## 架构结论

模型能稳定输出合法、原文绑定且大体覆盖目标的角色证据，但自然语言目标边界与树中
的标签边界并不稳定一致。把完整 TARGET span 当作候选入围硬门禁，会把语义相关但稍长
的目标短语直接变成零候选。

所以当前失败位于“角色化自然语言表示 → 精确字面节点门禁”的接口，而不是 JSON、
Provider、窗口、树规模或 parent 上下文。人工 Silver R1=16/16仍是上限证明，但依赖
人工选择与树标签一致的短语，不能直接代表生产用户语言。

## 冻结决定

- 停止在本18条数据上继续修改 Prompt；
- 保留角色化 Fact 作为查询结构，不把 R1 exact target gate 晋升为生产候选；
- 下一方案必须评估容忍 super/sub-span 和非字面表达的节点检索表示，例如受控的
  加权词法/BM25 与语义向量混合候选；
- 新方案仍由角色证据提供 TARGET/SCOPE/EXCLUSION 权重，但不能要求 TARGET 与节点名
  完整连续相等；
- 先在暴露开发集预注册一个最小方案，冻结后再使用新未见树确认；不宣称生产资格。
