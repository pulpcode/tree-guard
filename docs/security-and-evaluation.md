# TreeGuard 安全边界与评测方案

状态：设计基线
适用阶段：外网开发、单向导入、内网文件型 Shadow MVP

## 1. 安全目标

TreeGuard 必须同时满足：

1. 真实业务数据、内部代码和模型交互记录不离开内网；
2. 外网开发产物可以离线、可核验地单向导入；
3. LLM 无数据库凭证、无任意查询工具、无正式写权限；
4. 所有模型输出经过结构化校验和确定性风险门；
5. 内网测试失败时，可以通过白名单诊断信息协作，而不泄露敏感内容；
6. Shadow MVP 在物理上不存在生产数据库写路径。

## 2. 双区资产边界

| 外网通用 Core 可以持有 | 必须留在内网 |
|---|---|
| `TreeSnapshot`、`ChangeIntent`、`Overlay`、`Patch` 等抽象合同 | 真实树、节点名称、路径和 ID |
| 通用工作流、校验器、Diff、Trace 框架 | 真实历史版本和版本说明 |
| 完全虚构的领域数据和 Mock Adapter | Spring Boot 源码、内部 DTO、API 地址 |
| 契约测试、回放、评测和 Conformance 工具 | 邮件模板、Usage 真实数据和 VALUE |
| 不含真实业务内容的 Prompt 模板 | 含业务内容的 Prompt、模型输出和 Trace |
| 标准错误码和指标定义 | 真实 Gold、专家讨论和审批记录 |
| 锁定的依赖、SBOM、许可证清单 | 数据库凭证、密钥、网络拓扑和安全策略 |

外网通用 Core 不应包含任何仅适用于真实消防树的硬编码规则。

## 3. 单向导入包

外网交付包至少包含：

- 源码；
- 版本化 JSON Schema；
- File Adapter 和 Mock Adapter；
- 完全虚构的 fixtures；
- 单元测试、契约测试和端到端测试；
- Conformance CLI；
- 依赖锁文件；
- 可选 wheelhouse 或离线容器包；
- SBOM；
- 许可证清单；
- `SECURITY.md`；
- Transfer Manifest；
- 每个文件的校验值。

安全审查应覆盖：

- 源码和依赖扫描；
- 禁止遥测和自动更新；
- 运行时无外联；
- 无隐藏数据收集；
- 无数据库写连接器；
- 锁定所有传递依赖；
- wheel 或容器摘要可重复校验。

SBOM 只是可核验材料，不等于安全结论。

## 4. 内网向外网的诊断白名单

默认只允许：

- 固定枚举错误码；
- `PASS / FAIL`；
- 契约版本、通用包版本；
- 分桶后的数量、耗时、延迟和指标；
- 一次性随机案例编号；
- 经人工重写到无关虚构领域的最小复现。

禁止直接外传：

- 异常自由文本和堆栈；
- 内部目录、包名和类名；
- 真实节点名称、路径和 ID；
- Prompt、模型输出和 Trace；
- 数据库查询结果；
- 对低熵业务字段生成的确定性哈希；
- 全树一致的假名映射。

完整 `TreeSnapshot` 和 `TreeDiff` 都属于内网敏感制品。TreeDiff 的字段变化需要服务内网专家审查，因此 `before/after` 可能包含真实名称、label、remark、extension 或尚未分类的 metadata。它不得直接作为跨网诊断输出，也不得仅靠删除 VALUE 后就视为可外传。

跨网协作只允许输出固定错误码和聚合结果，例如变更类型计数、ERROR/WARNING 数量和分桶指标；不得输出 node delta、字段前后值、节点引用、snapshot/diff hash。若未来 CLI 增加完整 Diff 输出，必须明确标为内网命令，并与聚合 Conformance 报告分离。

低熵节点名称可能被字典反推。即使哈希看似不可读，也不能默认视为安全脱敏。一次性随机案例编号不得外传内部映射表。

## 5. 数据访问等级

模型默认只访问 Schema，不访问运行时 `VALUE`。

建议定义：

```text
SCHEMA_ONLY
AGGREGATED_EVIDENCE
REDACTED_SAMPLE
RAW_VALUE
```

- `SCHEMA_ONLY`：默认等级，名称、路径、类型、基数和审批后的 Overlay；
- `AGGREGATED_EVIDENCE`：只提供分桶统计或规则结果；
- `REDACTED_SAMPLE`：经过专项审批的最小脱敏样本；
- `RAW_VALUE`：MVP 禁止，未来需要单独授权、审计和保留策略。

Trace 尽量保存引用和版本信息，而不是复制敏感值。

## 6. 威胁模型与确定性门禁

### 6.1 Prompt 注入

树节点名称、描述、版本说明和文档文本都属于不可信输入。它们可能包含诱导模型改变目标或越权调用工具的文字。

缓解：

- 数据和系统指令在消息结构中隔离；
- LLM 只获得白名单候选和只读上下文；
- 无数据库凭证；
- 无任意工具调用；
- 输出只接受 JSON Schema；
- 所有动作由确定性代码重新验证。

### 6.2 编造节点 ID

缓解：

- 每次候选召回生成受控引用；
- 模型只能引用候选集合；
- Patch 编译器重新校验 `node_id`、版本和哈希；
- 未知 ID 立即失败，不尝试自动修复。

### 6.3 版本与索引过期

缓解：

- 固定基础树、Overlay、检索索引和 Usage Manifest 版本；
- 任一版本变化时将建议和 Patch 标记为 `STALE`；
- 过期依赖索引不得显示“无影响”；
- Patch 应带节点级前置条件和幂等键。

### 6.4 检索漏召回导致错误新增

缓解：

- 全树查重；
- 多通道宽召回；
- 单独评测召回和语义决策；
- 检索健康度不足时禁止从“未找到”推断“应该新增”；
- 高风险新增必须人工确认。

### 6.5 模型超时和格式异常

缓解：

- 在线最多两次顺序调用；
- 小候选上下文；
- 严格 Schema 输出；
- 有限重试；
- 超时、非法输出或不一致均转 `ABSTAIN` 或人工处理。

### 6.6 Shadow 自动化偏见

缓解：

- AI 建议先生成并冻结；
- 人工在看不到 AI 建议时独立作答；
- 人工作答冻结后再揭示并比较；
- 专家分歧进入仲裁或 ambiguity 集。

### 6.7 Trace 泄露

缓解：

- Trace 只保存在内网；
- 独立权限；
- 静态和传输加密；
- 明确保留期限；
- 导出报告只包含聚合指标。

## 7. 样本来源与用途

所有案例必须标注来源：

```text
REAL_HUMAN_GOLD
EXPERT_APPROVED_SYNTHETIC
AI_SYNTHETIC
DETERMINISTIC_STRESS
```

### 7.1 真实历史数据

历史版本可用于：

- 重建变更血缘；
- 发现疑似重复和结构问题；
- 提出待审查案例；
- 构建专家重新裁决的候选池。

历史版本不能直接作为 Gold，因为它只说明过去怎样操作，不能证明操作正确。

### 7.2 AI 合成数据

可以用于：

- JSON Schema 契约测试；
- 边界和异常测试；
- 压力和性能测试；
- 从已审批案例派生扰动；
- 开发阶段的检索和流程调试；
- 少量 few-shot 示例。

不能用于：

- 替代真实专家 Gold；
- 证明消防业务准确率；
- 由同一个模型同时生成、裁判并宣布正确；
- 改写或扩充冻结测试集后继续调参。

同一来源案例的所有变体必须留在同一个数据分区，避免训练/开发/测试泄漏。

## 8. 真实 Gold 的建立

一条合格 Gold 应满足：

1. 使用变更发生前的树快照；
2. 需求和必要上下文足够完整；
3. AI 建议已生成并冻结，但在人工作答前隐藏；
4. 领域专家独立判断业务主体、角色、场景和边界；
5. 信息树建设人员检查动作、路径、类型和基数；
6. 高影响或分歧案例由第二人复核或仲裁；
7. 最终结论显式标记为 `APPROVED`；
8. 记录可接受候选、正确动作、必要追问和拒答条件；
9. 冻结后不得用于调 Prompt、阈值或检索。

专家仍拿不准的案例不能强行标成确定动作，应进入：

- `DELIBERATING`；
- `NEED_EVIDENCE`；
- ambiguity/challenge 集。

一次发布可能修改不同子树，因此必须先基于 `node_id`、共同祖先和结构关系拆成原子变更簇，再由专家确认每一簇是否构成独立案例。

## 9. 评测指标

### 9.1 检索

- `Candidate Recall@5`；
- `Candidate Recall@20`；
- 正确候选的平均排名；
- 按词法重复、路径冲突、场景扩展等案例类型分组报告。

`Recall@5` 只统计 Gold 中确实存在可复用目标的案例。

### 9.2 选择性决策

- `Action Precision`：AI 明确作答案例中的正确比例；
- `Coverage`：AI 明确作答的案例比例；
- `Abstention Quality`：证据不足时是否正确追问或拒答；
- 高风险错误数：
  - 将不同语义错误复用；
  - 将已有语义错误新增；
  - 编造节点 ID；
  - 生成非法 Patch。

置信门不能直接使用 LLM 自报分数。应基于开发集校准检索召回、排序差距、结构一致性和规则信号。

### 9.3 人机协作

- 专家决策时间中位数变化；
- 专家修订意图卡的比例；
- AI 建议被接受、修订和拒绝的比例；
- 从 `OPEN` 到 `APPROVED` 的讨论轮次；
- 用户对推荐理由完整性的评价。

时间指标必须使用配对任务测量，不能只依赖主观估计。

### 9.4 工程与安全

- Qwen P50/P95 延迟；
- 超时率；
- 结构化输出失败率；
- Trace 关键步骤完整率；
- 过期 Patch 拦截率；
- 重复提交幂等性；
- 未授权外联次数；
- 正式数据库写入次数。

## 10. MVP 目标与解释

试点目标：

- `Candidate Recall@5 ≥ 90%`；
- `Action Precision ≥ 85%`；
- `Coverage ≥ 50%`；
- 专家决策时间中位数下降 `≥ 40%`；
- 非法、越权或过期 Patch 放行数 `= 0`；
- 未授权外联数 `= 0`；
- 正式数据库写入数 `= 0`；
- Trace 关键步骤完整率 `= 100%`。

30 条冻结案例只能支撑 MVP 可行性判断。在 50% Coverage 下，动作准确率可能只基于约 15 个明确回答案例，因此报告必须给出：

- 分子和分母；
- 样本类型分布；
- 置信区间；
- 被拒答案例；
- 全部高风险错误。

这些指标是进入“待审批 Patch 试点”的门槛，不是自动发布资格。

## 11. Go / No-Go

硬门槛：

- 至少 30 条真实冻结案例；
- 未授权外网访问为 0；
- 正式数据库写路径为 0；
- 非法或越权 Patch 通过校验为 0；
- Trace 关键步骤完整率 100%；
- 版本过期、模型异常、脏数据和 Prompt 注入均能安全拒绝；
- Transfer Manifest、依赖哈希和 SBOM 可核验。

质量指标未达到时：

- 继续 Shadow；
- 不扩大治理范围；
- 不增加写权限；
- 根据错误归因分别修复召回、排序、Prompt、Overlay 或规则；
- 不以微调模型作为默认补救。
